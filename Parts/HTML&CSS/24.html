Q231 — What is the difference between <progress> and <meter>? Medium

✅ Ideal answer <progress> represents completion progress for a task.

<meter> represents a scalar measurement within a known range.
🔁 Follow-up: Would you use <meter> for a file upload? No. File upload completion is task progress, so <progress> is more semantically appropriate.

💻 Code

index.html — Visual Studio Code
index.html
<label for="upload">Uploading</label>
<progress id="upload" value="70" max="100">70%</progress>

<label for="storage">Storage usage</label>
<meter id="storage" min="0" max="100" value="80">80%</meter>

Q232 — What is the purpose of <noscript>? Medium

✅ Ideal answer <noscript> provides fallback content for situations where scripting is disabled or unavailable, depending on where it's used.

It can also be used in the <head> with restrictions defined by HTML.
🔁 Follow-up: Does <noscript> mean "JavaScript failed"? Not exactly. It's primarily related to scripting being disabled or unsupported in the relevant context. It doesn't serve as a general JavaScript error handler.

💻 Code

index.html — Visual Studio Code
index.html
<noscript>
  JavaScript is required to use this application.
</noscript>

Q233 — What is the purpose of the <base> element? Hard

✅ Ideal answer <base> specifies the base URL and/or default target for resolving relative URLs in a document.

There can be only one <base> element in a document.
🔁 Follow-up: What happens if I write <base href="/app/"> and then <img src="images/logo.png">? The image URL is resolved relative to the base URL, so conceptually: /app/images/logo.png — depending on the document's URL resolution context.

💻 Code

index.html — Visual Studio Code
index.html
<head>
  <base href="https://example.com/app/">
</head>

<a href="jobs">Jobs</a>
<!-- Resolves to: https://example.com/app/jobs -->

🔴 Live demo — URL resolution

<base href="/app/">
href="jobs" → /app/jobs
src="images/logo.png" → /app/images/logo.png
href="https://external.com/x" → https://external.com/x (absolute — not affected)

Q234 — What is the Constraint Validation API? Hard

✅ Ideal answer The Constraint Validation API allows JavaScript to inspect and control the validity of form controls.

The validity property exposes a ValidityState object with flags such as valueMissing, typeMismatch, patternMismatch, tooShort, tooLong.

You can also use checkValidity(), reportValidity(), and setCustomValidity().
🔁 Follow-up: What's the difference between checkValidity() and reportValidity()? checkValidity() checks validity and returns true/false, but does not trigger the browser's validation UI.

reportValidity() checks validity and triggers the browser's validation UI if invalid.

💻 Code

script.js — Visual Studio Code
script.js
const input = document.querySelector("#email");

console.log(input.validity.valid);
console.log(input.validity.valueMissing);
console.log(input.validity.typeMismatch);

input.checkValidity();      // true/false, no UI
input.reportValidity();     // triggers native UI if invalid

input.setCustomValidity("Invalid email");
input.setCustomValidity(""); // clear

Q235 — What happens when the browser receives an HTML document? Hard

✅ Ideal answer At a high level:
  1. HTML bytes → decode characters → HTML parsing → DOM
  2. CSS parsing → CSSOM
  3. Both are combined → Render tree
  4. Then: Layout → Paint → Compositing
JavaScript can interact with and modify the DOM and CSSOM during this process.
🔁 Follow-up: Does the browser wait until all HTML is downloaded before rendering anything? Not necessarily. Browsers can progressively parse and render as resources become available, although scripts and other resources can affect parsing and rendering behavior.

↓

↓
3 DOM + CSSOM → Render Tree
↓
4 Layout (compute geometry)
↓
5 Paint (draw pixels)
↓
6 Composite (combine layers)

Q236 — What is referrerpolicy? Hard

✅ Ideal answer referrerpolicy controls what referrer information the browser sends when making certain requests/navigation from a document or resource.

Depending on the policy, the browser may send the full referring URL, only the origin, or no referrer at all.
🔁 Follow-up: Does referrerpolicy hide the user's IP address? No. It controls the HTTP Referer information, not the client's IP address.

💻 Code

index.html — Visual Studio Code
index.html
<a
  href="https://example.com"
  referrerpolicy="no-referrer"
>
  Visit
</a>

🔴 Live demo — Common policies

no-referrer Sends no referrer at all.
origin Sends only the origin (protocol + host + port).
same-origin Sends full referrer for same-origin, nothing cross-origin.
strict-origin Sends only the origin, and only over HTTPS → HTTPS.
strict-origin-when-cross-origin Full URL same-origin, origin only cross-origin, nothing on downgrade. Common modern default.

Q237 — You need to open an external link in a new tab. How would you write it safely? Hard

✅ Ideal answer <a href="https://example.com" target="_blank" rel="noopener noreferrer">

target="_blank" requests a new browsing context.
noopener prevents the opened page from accessing the opener through window.opener.
noreferrer additionally controls referrer information and provides opener protection in modern browsers.
🔁 Follow-up: Can I use only noopener? Yes, if I want opener protection but still want referrer information to be available according to the browser's referrer policy.

💻 Code

index.html — Visual Studio Code
index.html
<a
  href="https://example.com"
  target="_blank"
  rel="noopener noreferrer"
>
  Open Example
</a>

🔴 Live demo — Click both links

✅ Safe (rel="noopener noreferrer") ⚠️ Unsafe (no rel)

Both open MDN in a new tab. The green one is safe — the opened page can't reach window.opener.

Q238 — You have this HTML. What's wrong with it? Hard

✅ Ideal answer 
<p>
  <h2>Available Jobs</h2>
  <div>
    Frontend Developer
  </div>
</p>
The structure is invalid because a <p> element cannot contain arbitrary flow content such as <h2> or <div>.

A paragraph is intended for phrasing content, while <h2> and <div> are not phrasing content.
🔁 Follow-up: What might the browser do with invalid nesting like this? HTML parsing has error-recovery rules, so the browser may implicitly close the <p> before parsing elements that aren't allowed inside it. The resulting DOM may therefore differ from what the developer visually intended from the source.

💻 Code

index.html — Visual Studio Code
index.html
<!-- ✅ Valid structure -->
<section>
  <h2>Available Jobs</h2>

  <div>
    Frontend Developer
  </div>
</section>

<!-- Or, if the job is a self-contained item: -->
<section>
  <h2>Available Jobs</h2>

  <article>
    <h3>Frontend Developer</h3>
  </article>
</section>

🔴 Live demo — Invalid vs valid

❌ Invalid
<p>
  <h2>Available Jobs</h2>
  <div>
    Frontend Developer
  </div>
</p>

Browser will implicitly close the <p> before parsing the <h2>.

✅ Valid
<section>
  <h2>Available Jobs</h2>
  <div>
    Frontend Developer
  </div>
</section>

Clean structure — no parser error recovery needed.

Q239 — What is the difference between inputmode and type on an input? Medium

✅ Ideal answer type controls the input's semantics and validation — it tells the browser what kind of value is expected.

inputmode is a hint about which virtual keyboard layout to show on mobile — it does not change the input's validation or value.
🔁 Follow-up: Does inputmode affect desktop behavior? No — inputmode is specifically about virtual keyboards, so it has no meaningful effect on desktops with a physical keyboard.

💻 Code

index.html — Visual Studio Code
index.html
<input type="text" inputmode="numeric" name="otp">
<input type="text" inputmode="email" name="identifier">
<input type="text" inputmode="tel" name="phone">

🔴 Live demo — Try on a mobile device

On mobile: the virtual keyboard changes per field. On desktop: all three behave the same.

Q240 — What does pointer-events: none do, and how is it different from visibility: hidden? Medium

✅ Ideal answer pointer-events: none — element is still rendered, but clicks pass through to whatever is underneath.

visibility: hidden — element is invisible and removed from the accessibility tree, but still occupies layout space.
🔁 Follow-up: Can a keyboard user still interact with an element that has pointer-events: none? Yes — and this is a common misconception. pointer-events: none only disables pointer-based interaction (mouse, touch, stylus). Keyboard focus, keyboard activation, screen readers, and programmatic events still work.

💻 Code

style.css — Visual Studio Code
style.css
.overlay {
  pointer-events: none; /* visible, but clicks pass through */
}

.hidden-btn {
  visibility: hidden; /* invisible, but keeps layout space */
}

🔴 Live demo — Click the button in each box

Overlay (clicks pass through)

The overlay is visible but transparent to clicks — the button beneath is clickable.

visibility: hidden

The button is invisible, keeps its space, and is removed from the accessibility tree.
