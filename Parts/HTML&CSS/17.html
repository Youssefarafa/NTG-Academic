Q161 — What is the difference between a pseudo-class and a pseudo-element? Medium

✅ Ideal answer A pseudo-class targets an element based on a particular state or condition (e.g., :hover, :focus, :first-child).

A pseudo-element targets a specific part of an element or creates a generated piece of content (e.g., ::first-line, ::before).
🔁 Follow-up: Why does ::before usually require content? Because ::before creates a generated pseudo-element, and the content property controls its generated content. Even an empty value such as content: ""; is commonly used when the pseudo-element is only needed for styling.

💻 Code

style.css — Visual Studio Code
style.css
/* Pseudo-class */
.btn-demo:hover { background: #ef4444; }

/* Pseudo-element */
.pseudo-demo::before { content: "👉 "; }

Q162 — What is the difference between ::before and ::after? Easy → Medium

✅ Ideal answer Both create pseudo-elements associated with an element.

::before is inserted as the first child of the element's generated content.
::after is inserted as the last child.
🔁 Follow-up: Are ::before and ::after real DOM elements? No. They are CSS-generated pseudo-elements and aren't represented as normal DOM nodes that you can select with JavaScript.

💻 Code

style.css — Visual Studio Code
style.css
.title-demo::before { content: "★ "; color: #f59e0b; }
.title-demo::after { content: " →"; color: #10b981; }

Q163 — What is the difference between :nth-child() and :nth-of-type()? Medium

✅ Ideal answer :nth-child() counts all siblings.

:nth-of-type() counts only siblings of the same element type.

Given a div with an h2 followed by two p tags: p:nth-child(2) selects the first paragraph (since it's the 2nd child overall). p:nth-of-type(2) selects the second paragraph.
🔁 Follow-up: Why? Because nth-child() counts all children, while nth-of-type() counts only elements of the same type.

💻 Code

style.css — Visual Studio Code
style.css
li:nth-child(2) { color: red; }
li:nth-of-type(3) { color: blue; }

Q164 — What is the difference between :not(), :is(), and :where()? Hard

✅ Ideal answer :not() matches elements that don't match the selector inside it.

:is() allows grouping alternative selectors and takes the specificity of its most specific argument.

:where() has similar grouping functionality but always contributes zero specificity. This makes it useful for easily overridable styles.
🔁 Follow-up: What's the key specificity difference between :is() and :where()? :is() takes the specificity of its most specific argument, while :where() has zero specificity.

💻 Code

style.css — Visual Studio Code
style.css
:is(h4, h5, h6) { color: #4f46e5; }
:where(.card, .panel) { background: #e0e7ff; padding: 10px; }
button:not(.disabled) { background: #10b981; }

Q165 — What does the CSS :has() pseudo-class do? Hard

✅ Ideal answer :has() allows selecting an element based on whether it has a matching relative selector inside its relational scope.

For example, .card:has(img) selects .card elements that contain an img descendant.
🔁 Follow-up: Why is :has() sometimes called a "parent selector"? Because it allows styling an element based on something inside it, which historically wasn't possible with normal CSS selectors.

💻 Code

style.css — Visual Studio Code
style.css
.card:has(img) {
  border-color: #10b981;
  background: #ecfdf5;
}

Q166 — What does currentColor mean in CSS? Medium

✅ Ideal answer currentColor represents the element's computed color value.

For example, if an element has color: blue; and a border: 1px solid currentColor;, the border will be blue.
🔁 Follow-up: Can an SVG use currentColor? Yes. An SVG using fill: currentColor; can inherit the text color of its parent.

💻 Code

style.css — Visual Studio Code
style.css
.color-box {
  color: #4f46e5;
  border: 4px solid currentColor;
}

Q167 — What is object-fit, and why is it useful for images? Medium

✅ Ideal answer object-fit controls how replaced content such as an image fits inside its specified box.

cover: Fills the box while preserving aspect ratio (may crop).
contain: Entire image visible while preserving aspect ratio (may leave empty space).
🔁 Follow-up: When would you use contain instead of cover? For product images, logos, or assets where I don't want important parts of the image cropped.

💻 Code

style.css — Visual Studio Code
style.css
img {
  width: 150px;
  height: 150px;
  object-fit: cover; /* or contain */
}

Q168 — What is the difference between object-fit and background-size: cover? Hard

✅ Ideal answer object-fit controls how the content of a replaced element such as <img> fits within its box.

background-size: cover controls how a CSS background image is sized inside an element.

Semantically, an <img> is generally preferable when the image is actual content. A background image is often more appropriate when the image is decorative.
🔁 Follow-up: For a product photo in an e-commerce application, which would you prefer? Usually an <img> because the product image is meaningful content, and I can also provide useful alt text and responsive image behavior.

💻 Code

style.css — Visual Studio Code
style.css
.img-content { object-fit: cover; }
.bg-image { background-size: cover; background-position: center; }

Q169 — What is aspect-ratio and why is it useful? Medium

✅ Ideal answer aspect-ratio defines the preferred width-to-height ratio of an element.

It helps maintain consistent dimensions while the element's size changes. It's especially useful for image cards, video containers, responsive media, and preventing layout shifts.
🔁 Follow-up: Can you use aspect-ratio without explicitly setting both width and height? Yes. The browser can use the aspect ratio together with a definite dimension or available size to determine the other dimension.

💻 Code

style.css — Visual Studio Code
style.css
.card-image {
  width: 100%;
  aspect-ratio: 16 / 9;
  object-fit: cover;
}

Q170 — What is will-change, and why shouldn't it be overused? Hard

✅ Ideal answer will-change tells the browser that an element is likely to change certain properties, potentially allowing the browser to optimize rendering ahead of time.

It should be used carefully because excessive or unnecessary use can increase memory consumption and create additional rendering resources rather than improving performance.
🔁 Follow-up: Would you put this globally? `* { will-change: transform; }` No. That would be excessive and potentially harmful. I'd use it selectively for elements that have a known upcoming animation or transformation.

💻 Code

style.css — Visual Studio Code
style.css
.card {
  will-change: transform; /* Hint to browser */
}
