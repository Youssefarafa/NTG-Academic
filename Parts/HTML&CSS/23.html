Q221 — What is tabindex? Medium

✅ Ideal answer tabindex controls whether an element can receive focus through keyboard navigation and can influence its position in the sequential focus order.

tabindex="0" allows an otherwise non-focusable element to participate in the normal tab order.
tabindex="-1" allows the element to be programmatically focused but normally removes it from sequential keyboard navigation.
🔁 Follow-up: What about tabindex="5"? Positive tabindex values create an explicit focus order and are generally discouraged because they can make keyboard navigation confusing and difficult to maintain. Prefer natural document order and tabindex="0" / -1 when appropriate.

💻 Code

index.html — Visual Studio Code
index.html
<!-- Natural tab order (recommended) -->
<div tabindex="0">
  Focusable content
</div>

<!-- Programmatic focus only -->
<div tabindex="-1">
  Focusable via JS only
</div>

<!-- ⚠️ Positive values — discouraged -->
<div tabindex="5">
  Custom order
</div>

🔴 Live demo — Press Tab inside the box

tabindex="-1" Skipped by Tab, focused by JS only

Q222 — What is an accessible name? Hard

✅ Ideal answer An accessible name is the name that assistive technologies can use to identify an interface element to the user.

The visible text Save can provide a button's accessible name. For an input, a <label> can provide the accessible name.

Other mechanisms can also contribute to an accessible name, including ARIA attributes such as aria-label and aria-labelledby.
🔁 Follow-up: Why is this important? A screen reader needs a meaningful name to announce controls to the user. Without an accessible name, a control may be announced without enough information for the user to understand its purpose.

💻 Code

index.html — Visual Studio Code
index.html
<!-- Accessible name from visible text -->
<button>
  Save
</button>

<!-- Accessible name from a label -->
<label for="email">Email</label>
<input id="email">

<!-- Accessible name from ARIA -->
<button aria-label="Close dialog">✕</button>

🔴 Live demo — Inspect accessible names

The first button's accessible name is "Save". The second button's accessible name is "Close dialog" (from aria-label), not ✕. The input's accessible name is "Email" from the <label>.

Q223 — Why should you prefer native HTML controls over custom controls? Hard

✅ Ideal answer Native controls already provide a lot of behavior that custom controls would otherwise need to recreate. For example, a native <button> provides:
  • Semantics
  • Keyboard interaction
  • Focus behavior
  • Browser integration
  • Assistive technology support
A custom <div>-based button requires developers to implement much of this behavior themselves. Therefore, when a native element matches the required behavior, I prefer using it.
🔁 Follow-up: When would you create a custom control? When the required UI behavior cannot be adequately represented by existing native controls or components, while ensuring that the custom control implements the required keyboard, focus, semantic, and assistive-technology behavior.

💻 Code

index.html — Visual Studio Code
index.html
<!-- ✅ Native — full behavior for free -->
<button>
  Submit
</button>

<!-- ⚠️ Custom — you must re-implement everything -->
<div role="button" tabindex="0">
  Submit
</div>

⚠️ <div role="button">

Submit

Needs manual keyboard handling (Enter/Space) and is only announced correctly because of the role.

Q224 — What is the difference between aria-hidden="true" and removing an element from the DOM? Hard

✅ Ideal answer aria-hidden="true" tells assistive technologies that the element and its subtree should not be exposed in the accessibility tree.

The element still exists in the DOM and can still be affected by CSS and JavaScript.

Removing the element from the DOM is different: the element no longer exists as part of the document structure.
🔁 Follow-up: Should you put aria-hidden="true" on a focusable element? Generally no. If an element can receive focus but is hidden from assistive technologies, keyboard and screen-reader users can encounter confusing or inaccessible behavior.

Also, if content is visually hidden and should truly be unavailable to users, the appropriate mechanism depends on the intended behavior.

💻 Code

index.html — Visual Studio Code
index.html
<!-- Hidden from AT, still in the DOM -->
<span aria-hidden="true">★</span>

<!-- Removed entirely from the DOM -->
<!-- (element is not present at all) -->

Q225 — What is the difference between hidden, aria-hidden, and CSS hiding? Hard

✅ Ideal answer These mechanisms have different meanings:
  • hidden (HTML attribute) — element is not currently relevant/presented; user agents generally don't render it.
  • aria-hidden="true" — hides the element from the accessibility tree, but does not inherently hide it visually.
  • CSS display: none — removes the element from normal rendering/layout.
  • CSS visibility: hidden — keeps layout space while making it visually hidden.
🔁 Follow-up: Can I use aria-hidden="true" to hide a modal visually? No. aria-hidden is not a visual hiding mechanism.

💻 Code

index.html
<div hidden>Hidden via attribute</div>

<div aria-hidden="true">Hidden from AT only</div>

<div style="display: none;">Hidden via CSS</div>

<div style="visibility: hidden;">Invisible but keeps space</div>

Q226 — What is the difference between hidden and display: none? Hard

✅ Ideal answer The hidden attribute is an HTML semantic/state mechanism indicating that the element is not currently relevant or should not be presented.

Browsers typically render it similarly to display: none by default. But conceptually they're different:
  • hidden → HTML state/meaning
  • display: none → CSS presentation rule
JavaScript can toggle the HTML state: element.hidden = false;
🔁 Follow-up: Can CSS override the visual effect of hidden? Yes, CSS can potentially override the user-agent styling associated with the hidden state. But doing so carelessly can create a mismatch between the HTML state and what users/assistive technologies experience.

💻 Code

index.html — Visual Studio Code
index.html
<div hidden>Hidden content</div>

<!-- Toggle via JS -->
<script>
  element.hidden = false; // show
  element.hidden = true;  // hide
</script>

🔴 Live demo — Toggle the hidden attribute

This element toggles via the hidden attribute

The button uses el.hidden = !el.hidden — that's the semantic HTML state, not display: none.

Q227 — What is the purpose of <details> and <summary>? Medium

✅ Ideal answer <details> represents a disclosure widget that the user can open and close.

<summary> provides the visible label that controls the disclosure.

The browser provides the basic open/close behavior without requiring JavaScript. You can also control the initial state using open.
🔁 Follow-up: How would you know whether <details> is currently open? You can check whether the open attribute is present. With JavaScript: details.open

💻 Code

index.html — Visual Studio Code
index.html
<details>
  <summary>What is Angular?</summary>

  <p>
    Angular is a web framework for building applications.
  </p>
</details>

<!-- Open by default -->
<details open>
  <summary>Details</summary>
  <p>Visible initially.</p>
</details>

Q228 — What is the purpose of the <dialog> element? Medium

✅ Ideal answer <dialog> represents a dialog box or other interactive modal/non-modal dialog.

JavaScript can open it as a modal using dialog.showModal(); and close it with dialog.close();.

A modal dialog opened with showModal() is placed into the browser's top layer and blocks interaction with the rest of the document.
🔁 Follow-up: What's the difference between show() and showModal()? show() → non-modal dialog.
showModal() → modal dialog that blocks interaction with the rest of the document.

💻 Code

index.html — Visual Studio Code
index.html
<dialog id="confirmDialog">
  <p>Are you sure?</p>
  <button type="button">Cancel</button>
  <button type="button">Confirm</button>
</dialog>

<script>
  dialog.showModal(); // modal
  dialog.close();     // close
</script>

Q229 — What is the <datalist> element? Medium

✅ Ideal answer <datalist> provides a list of suggested values for an input.

The user can generally type a custom value instead of being restricted to the provided suggestions.
🔁 Follow-up: What's the difference between <datalist> and <select>? select → choose from defined options only.
datalist → provides suggestions, but the user can generally enter another value.

💻 Code

index.html — Visual Studio Code
index.html
<label for="browser">Browser</label>

<input
  id="browser"
  name="browser"
  list="browsers"
>

<datalist id="browsers">
  <option value="Chrome">
  <option value="Firefox">
  <option value="Edge">
</datalist>

🔴 Live demo — Start typing in the input

You can pick one of the suggestions, or type any custom value.

Q230 — What is the purpose of the <output> element? Medium

✅ Ideal answer <output> represents the result of a calculation or user action.

The for attribute can identify the controls that contributed to the result.
🔁 Follow-up: Is <output> the same thing as <input type="text">? No. <output> has semantic meaning as a result of a calculation or user action, while an input represents user input.

💻 Code

index.html — Visual Studio Code
index.html
<form oninput="result.value = Number(a.value) + Number(b.value)">
  <input id="a" type="number" value="10">
  <input id="b" type="number" value="20">

  <output name="result" for="a b">
    30
  </output>
</form>
