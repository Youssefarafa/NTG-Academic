Q61 — What is the difference between <form> and <fieldset>? Easy → Medium

✅ Ideal answer <form> represents a complete form that contains controls and can be submitted.

<fieldset> is used to group related form controls together semantically.
🔁 Follow-up: What is the purpose of <legend>? <legend> provides a caption or accessible name for the <fieldset>.
🔁 Follow-up: What is the difference between action and method? action
→ where the form data is sent
method
→ how the data is sent

For example:
<form action="/users" method="post">
🔁 Follow-up: What is the difference between <fieldset> and <legend>? <fieldset> groups related form controls.
<legend> provides a caption/name for that group.

Example:
<fieldset>
  <legend>Account Type</legend>

  <label>
    <input type="radio" name="type" value="employee">
    Employee
  </label>

  <label>
    <input type="radio" name="type" value="recruiter">
    Recruiter
  </label>
</fieldset>

This is particularly useful for accessibility because assistive technologies can understand that the controls belong to the same conceptual group.

🔁 Follow-up: Would you use a <div> instead?
If I need an actual semantic form grouping, <fieldset> is preferable because it communicates the relationship.

  <fieldset>
    <legend>Personal Information</legend>
    <label for="name">Name</label>
    <input id="name" name="name">
    
    <label for="email">Email</label>
    <input id="email" name="email">
  </fieldset>
</form>

Q62 — What is the difference between client-side and server-side validation? Medium

✅ Ideal answer Client-side validation happens in the browser before the request is sent to the server. It provides fast feedback and improves user experience.

Server-side validation happens on the backend and is essential because the client cannot be trusted.
🔁 Follow-up: Why can't we rely only on Angular validation? Because a user can bypass the Angular application entirely and send requests directly to the API using tools such as Postman or custom scripts.

Q63 — What is the difference between <input type="submit"> and <button type="submit">? Easy → Medium

✅ Ideal answer Both can submit a form when they're associated with a form.

<input type="submit"> is an input control whose displayed content is controlled through its value.

<button type="submit"> is a button element whose content can contain text and, depending on the allowed content, richer markup.
🔁 Follow-up: What is the default type of a <button> inside a form? The default behavior is submit, so it's good practice to explicitly specify the type.

💻 Code

index.html — Visual Studio Code
index.html
<!-- Input: only plain text via value -->
<input type="submit" value="Login">

<!-- Button: can contain icons, spans, rich HTML -->
<button type="submit">
  <span style="color:red;">★</span> Login
</button>

Q64 — What is the difference between type="button" and type="submit"? Easy

✅ Ideal answer type="submit" submits the associated form.

type="button" is a normal button and doesn't submit the form by default.
🔁 Follow-up: What would you use for opening a modal? Usually: <button type="button">Open Modal</button> because opening a modal is an action, not a form submission.

Q65 — What happens when an HTML form is submitted? Medium

✅ Ideal answer When a form is submitted, the browser identifies the successful form controls, constructs the form data, and depending on the form's method and action, sends a request to the specified URL.
🔁 Follow-up: What happens to disabled form controls during native submission? Disabled controls are generally not included in the submitted form data.

💻 Code

index.html — Visual Studio Code
index.html
<form action="/login" method="POST">
  <input name="username" value="Youssef">
  <input name="password" value="secret" disabled>
  <button type="submit">Login</button>
</form>

Q66 — What are "successful controls" in HTML forms? Hard

✅ Ideal answer Successful controls are form controls whose names and values are included when the browser constructs the form data for submission.

For example, a disabled input is generally not successful and won't be included. Checkboxes that are not checked are also generally not included. Controls typically need an appropriate name to contribute a name-value pair.
🔁 Follow-up: If I have an unchecked checkbox (active=true), will it be submitted? No. An unchecked checkbox is generally not included in native form submission at all. If the backend needs an explicit false, the application needs to handle that appropriately.

💻 Code

index.html — Visual Studio Code
index.html
<input type="checkbox" name="active" value="true">
<!-- If unchecked, this is NOT submitted. -->

Q67 — What is the action attribute of a <form>? Easy → Medium

✅ Ideal answer The action attribute specifies the URL where the form submission should be sent.

For example: <form action="/api/users" method="POST">
The browser submits the form to /api/users.
🔁 Follow-up: What happens if action isn't specified? The form submits to the current document's URL by default.

💻 Code

index.html — Visual Studio Code
index.html
<form action="/api/users" method="POST">
  <input name="name">
  <button type="submit">Submit</button>
</form>

Q68 — What is the difference between GET and POST in HTML forms? Medium

✅ Ideal answer With a GET form submission, the form data is encoded into the URL query string.

With POST, the form data is sent in the request body.

GET is appropriate for search/filter forms where representing the state in the URL is useful. POST is commonly used when submitting data that causes a server-side operation.
🔁 Follow-up: Can GET requests modify data? Technically a server could be implemented that way, but according to HTTP semantics, GET should be safe and used for retrieving representations rather than performing state-changing operations.
🔁 Follow-up: Is POST automatically more secure than GET? No. The choice between GET and POST is not itself an encryption mechanism. Sensitive data should be protected using HTTPS and appropriate server-side security.

💻 Code

index.html — Visual Studio Code
index.html
<!-- GET -->
<form method="GET">
  <input name="search" value="laptop">
</form>

<!-- POST -->
<form method="POST">
  <input name="username" value="Youssef">
</form>

Q69 — What is HTML escaping and why is it important? Medium → Hard

✅ Ideal answer HTML escaping converts special characters into safe HTML representations so that user-provided text isn't interpreted as HTML markup.

For example: < becomes &lt;, > becomes &gt;, and & becomes &amp;.

This is important when displaying untrusted content because it can help prevent HTML injection and XSS vulnerabilities.
🔁 Follow-up: Is escaping alone enough to prevent all XSS? No. XSS prevention depends on the context and proper output encoding, safe APIs, sanitization where appropriate, and framework protections. Different contexts such as HTML, JavaScript, CSS, and URLs require different handling.

💻 Code

index.html — Visual Studio Code
index.html
<!-- User input: <script>alert(1)</script> -->

<!-- ❌ Unsafe: Renders as HTML -->
<div><script>alert(1)</script></div>

<!-- ✅ Safe: Escaped -->
<div>&lt;script&gt;alert(1)&lt;/script&gt;</div>

Q70 — What is XSS? Hard

✅ Ideal answer XSS, or Cross-Site Scripting, is a vulnerability where an attacker manages to cause malicious JavaScript or other executable content to run in another user's browser in the context of a trusted website.

For example, if an application unsafely renders user-controlled HTML, an attacker could inject a script that executes when another user views the content.

Types include: Stored XSS, Reflected XSS, and DOM-based XSS.
🔁 Follow-up: Does Angular protect against XSS? Angular provides built-in protections by escaping/interpreting template-bound values safely and sanitizing certain potentially dangerous values and contexts. However, developers can still introduce vulnerabilities by bypassing Angular's security mechanisms.
🔁 Follow-up 2: What is the danger of using innerHTML with user input? If untrusted input is inserted as HTML without proper sanitization, an attacker may inject malicious markup or scripts, creating an XSS vulnerability.

💻 Code

app.js — Visual Studio Code
app.js
// ❌ DANGEROUS: XSS Vulnerability
const userInput = "<img src=x onerror=alert('XSS!')>";
document.getElementById('output').innerHTML = userInput;

// ✅ SAFE: Uses textContent (escapes HTML)
document.getElementById('output').textContent = userInput;
