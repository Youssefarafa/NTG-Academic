Q181 — What is the CSS Cascade? Medium

✅ Ideal answer The CSS cascade is the process the browser uses to determine which CSS declarations should win when multiple rules apply to the same element.

Factors considered: Origin and importance, Cascade layers, Specificity, and Source order.
🔁 Follow-up: Is specificity the only thing that determines which CSS rule wins? No. Specificity is only one part of the cascade. Importance, origin, cascade layers, and source order can also affect the result.

💻 Code

style.css — Visual Studio Code
style.css
p { color: blue; }
p { color: red; } /* This wins due to source order */

Q182 — What is CSS inheritance? Easy

✅ Ideal answer Inheritance means some CSS properties can automatically receive their value from the parent element.

Properties like color, font-family, and line-height commonly inherit.
Others like margin, padding, border, and width do not normally inherit.
🔁 Follow-up: Can you force a property to inherit? Yes. Using color: inherit; explicitly tells the element to use the inherited value.

💻 Code

style.css — Visual Studio Code
style.css
body { color: #333; }

.child { color: inherit; } /* Forces inheritance */

Q183 — What do inherit, initial, unset, and revert mean? Hard

✅ Ideal answer
  • inherit: Takes the value from the parent.
  • initial: Resets to the CSS initial value (e.g., black for color).
  • unset: Inherits if the property is normally inherited, otherwise behaves like initial.
  • revert: Rolls back to the browser/user-agent stylesheet default.
🔁 Follow-up: What's the difference between initial and unset? initial always uses the property's initial value. unset behaves like inherit if the property is inherited, otherwise it behaves like initial.

💻 Code

style.css — Visual Studio Code
style.css
button {
  all: revert; /* Restores default browser button styling */
}

Q184 — What is the difference between :focus, :focus-visible, and :focus-within? Medium → Hard

✅ Ideal answer
  • :focus matches an element whenever it has focus.
  • :focus-visible applies focus styles when the browser determines a visible focus indicator is appropriate (usually keyboard navigation).
  • :focus-within matches an element when it or one of its descendants has focus.
🔁 Follow-up: Why shouldn't you simply do `*:focus { outline: none; }`? Because removing focus indicators can make keyboard navigation difficult or impossible to follow, which is an accessibility problem.

💻 Code

style.css — Visual Studio Code
style.css
button:focus-visible { outline: 3px solid orange; }
.form-group:focus-within { border-color: blue; }

🔴 Live demo — Use the Tab key

Q185 — What is prefers-reduced-motion and why is it important? Medium

✅ Ideal answer prefers-reduced-motion is a media feature that allows us to detect when a user has requested reduced motion in their OS or browser settings.

This allows us to reduce potentially uncomfortable animations for users who prefer less motion.
🔁 Follow-up: Would you completely remove every animation? Not necessarily. I'd reduce or disable animations that can cause discomfort while preserving useful visual feedback where appropriate.

💻 Code

style.css — Visual Studio Code
style.css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms;
    transition-duration: 0.01ms;
    scroll-behavior: auto;
  }
}

🔴 Live demo (Reduced motion simulation)

If your OS has "Reduce Motion" enabled, this spinner stops.

Q186 — What is the difference between display: flex and display: inline-flex? Medium

✅ Ideal answer Both create a flex formatting context for their children.

display: flex makes the container behave as a block-level flex container (takes full width).
display: inline-flex makes the container behave as an inline-level flex container (shrinks to fit content).
🔁 Follow-up: Does inline-flex mean its children become inline elements? No. The container participates as an inline-level element, but its children are still flex items.

💻 Code

style.css — Visual Studio Code
style.css
.flex { display: flex; } /* Block-level */
.inline-flex { display: inline-flex; } /* Inline-level */

.badge { display: inline-flex; align-items: center; }

Q187 — What is display: contents? Hard

✅ Ideal answer display: contents causes the element's own box to not be generated for layout, while its children can participate in the parent's layout as if the wrapper box wasn't there.
🔁 Follow-up: Does display: contents remove the element from the DOM? No. The element remains in the DOM; its own CSS box is just not generated in the usual way.

💻 Code

style.css — Visual Studio Code
style.css
.wrapper {
  display: contents;
}

Q188 — What is contain in CSS? Hard

✅ Ideal answer CSS contain allows an element to limit how its layout, paint, size, or style can affect the rest of the page.

For example, contain: layout paint; isolates parts of the page so changes inside them don't require as much work elsewhere, improving performance.
🔁 Follow-up: Why can containment improve performance? Because it gives the browser stronger boundaries about which parts of the rendering tree can be affected by changes, reducing the amount of layout or paint work required.

💻 Code

style.css — Visual Studio Code
style.css
.card {
  contain: layout paint;
}

🔴 Live demo

Isolated Card

This card has contain: layout paint. Changes inside it won't cause the rest of the page to reflow.

Q189 — What is the difference between visibility: collapse and visibility: hidden? Hard

✅ Ideal answer visibility: hidden makes an element invisible while generally preserving its layout space.

visibility: collapse has special behavior depending on the layout context. It was designed primarily around table rows/columns and can behave differently in other layout systems.
🔁 Follow-up: Would you use visibility: collapse to hide a normal div? Usually no. For a normal element, I'd choose display: none, visibility: hidden, or another technique depending on whether I need to preserve layout and interaction.

💻 Code

style.css — Visual Studio Code
style.css
tr {
  visibility: collapse; /* Collapses the table row */
}

Q190 — What is CSS @supports, and how can it help with progressive enhancement? Medium → Hard

✅ Ideal answer @supports allows CSS to conditionally apply rules based on whether the browser supports a particular CSS feature.

The browser uses the enhanced version only if it supports the feature. This is useful for progressive enhancement and graceful fallbacks.
🔁 Follow-up: Can you check multiple conditions? Yes. You can use and, or, and not (e.g., @supports (display: grid) and (gap: 1rem)).

💻 Code

style.css — Visual Studio Code
style.css
.card { display: block; }

@supports (display: grid) {
  .card {
    display: grid;
    gap: 1rem;
  }
}
