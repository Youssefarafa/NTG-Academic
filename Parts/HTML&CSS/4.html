Q31 — What is the difference between <head> and <body>? Easy

✅ Ideal answer The <head> contains metadata and resources about the document, such as the <title>, meta tags, stylesheets, and scripts that need to be loaded.

The <body> contains the actual content that is rendered and displayed to the user, such as headings, paragraphs, images, forms, and buttons.
🔁 Follow-up: Is everything inside <head> invisible to the user? Most of the content isn't directly displayed, but some elements can affect browser behavior or load resources. For example, <title> appears in the browser tab.

💻 Code

index.html — Visual Studio Code
index.html
<head>
  <title>My Page Title</title>
  <meta charset="UTF-8">
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <h1>Welcome to My Page</h1>
  <p>This is visible content.</p>
</body>

Q32 — What is the purpose of the <meta viewport> tag? Easy → Medium

✅ Ideal answer The viewport meta tag tells the browser how to control the page's dimensions and scaling on mobile devices.

The common version is:
<meta name="viewport" content="width=device-width, initial-scale=1.0">
🔁 Follow-up: What can happen if we don't include it on a mobile page? The browser may use a wider virtual viewport, causing the page to appear zoomed out and making responsive layouts behave incorrectly.

Q33 — What is the purpose of the DOCTYPE declaration? Easy

✅ Ideal answer <!DOCTYPE html> tells the browser that the document should be interpreted using the modern HTML standard and helps the browser use standards mode instead of quirks mode.
🔁 Follow-up: Is DOCTYPE an HTML element? No. It's a document type declaration, not an HTML element.

Q34 — What is the difference between localStorage, sessionStorage, and cookies? Medium

✅ Ideal answer All three can store client-side data, but they behave differently.
  • localStorage persists until it's explicitly cleared.
  • sessionStorage usually persists only for the lifetime of the browser tab/session.
  • Cookies are small pieces of data associated with HTTP requests and can be configured with attributes such as HttpOnly, Secure, and SameSite.
🔁 Follow-up: Which is safer for storing an authentication token? It depends on the architecture and threat model. For tokens that should be protected from JavaScript access, an HttpOnly, Secure cookie can reduce XSS exposure compared with storing the token in localStorage.

💻 Code

app.js — Visual Studio Code
app.js
// localStorage
localStorage.setItem('theme', 'dark');
console.log(localStorage.getItem('theme'));

// sessionStorage
sessionStorage.setItem('sessionId', 'abc123');

// Cookies
document.cookie = 'username=Youssef; path=/';

Q35 — What is the difference between async and defer for scripts? Medium

✅ Ideal answer Both async and defer allow scripts to download without blocking HTML parsing.

With async, the script executes as soon as it finishes downloading, so order between multiple async scripts isn't guaranteed.

With defer, scripts execute after HTML parsing is complete, and they maintain their document order.
🔁 Follow-up: Which would you prefer when one script depends on another? defer is generally more appropriate when script execution order matters.
🔁 Follow-up: Why can a normal <script> block HTML parsing? A classic script without async or defer can pause HTML parsing while the browser fetches and executes the script.

The parser encounters the script, and the browser may need to stop parsing, fetch the script, execute it, and then continue parsing.

This matters because JavaScript can modify the document while it is being parsed.
🔁 Follow-up: How does defer change this? A deferred external script can be downloaded without blocking HTML parsing, and it executes after the document has been parsed, before DOMContentLoaded.

<script src="app.js" defer></script>
🔁 Follow-up: What is the difference between async and defer for scripts? Both allow external scripts to be fetched without simply blocking HTML parsing during the download, but their execution behavior differs.

defer
<script src="app.js" defer></script>
  • Downloads while HTML parsing continues.
  • Executes after HTML parsing finishes.
  • Deferred scripts preserve their order relative to each other.
  • Executes before DOMContentLoaded.
async
<script src="analytics.js" async></script>
  • Downloads while parsing continues.
  • Executes as soon as the script is ready.
  • Can interrupt HTML parsing for execution.
  • Multiple async scripts don't guarantee execution order.
Conceptually: 
defer
→ download parallel
→ execute after parsing
→ ordered

async
→ download parallel
→ execute whenever ready
→ not ordered
🔁 Follow-up: When would you use async? For independent scripts where execution order relative to other scripts or document parsing isn't important, such as certain analytics or third-party scripts.

💻 Code

index.html — Visual Studio Code
index.html
<!-- Normal: Blocks parsing -->
<script src="script1.js"></script>

<!-- Async: Downloads in parallel, executes ASAP -->
<script src="script2.js" async></script>

<!-- Defer: Downloads in parallel, executes after parsing -->
<script src="script3.js" defer></script>

Q36 — What is accessibility in HTML? Easy → Medium

✅ Ideal answer Web accessibility means making websites usable by people with different abilities, including users who rely on assistive technologies such as screen readers or keyboard navigation.
🔁 Follow-up: Should we use ARIA everywhere? No. Native semantic HTML should be preferred whenever possible.
🔁 Follow-up: What is web accessibility, and why is it important? Web accessibility means designing and developing websites so that people with different abilities can use and interact with them effectively. It includes users who may rely on screen readers, keyboard navigation, voice control, magnification, or other assistive technologies. HTML plays a major role because semantic HTML provides meaningful structure and native behavior to browsers and assistive technologies — a real <button> is generally better than a <div onclick> because the native button already provides appropriate semantics and interaction behavior.
🔁 Follow-up: What is WCAG? WCAG stands for Web Content Accessibility Guidelines. It's a set of guidelines for making web content more accessible.

💻 Code

index.html — Visual Studio Code
index.html
<!-- ❌ Bad -->
<div onclick="submitForm()">Submit</div>

<!-- ✅ Good -->
<button type="submit">Submit</button>
<label for="name">Name</label>
<input id="name" type="text">

Q37 — What is ARIA? Medium

✅ Ideal answer ARIA stands for Accessible Rich Internet Applications. It provides attributes that communicate roles, states, and properties of UI elements to assistive technologies.

Example: <button aria-label="Close dialog">×</button>
🔁 Follow-up: Give me examples of ARIA attributes. Examples include aria-label, aria-labelledby, aria-describedby, aria-expanded, aria-hidden, aria-selected.
🔁 Follow-up: Should you use ARIA everywhere? No.
A good principle is:
Use native HTML semantics whenever possible, and use ARIA when necessary to communicate semantics that native HTML doesn't provide.

💻 Code

index.html — Visual Studio Code
index.html
<button aria-label="Close dialog">×</button>
<button aria-expanded="true">Toggle Menu</button>

Q38 — What is the difference between aria-label and aria-labelledby? Medium → Hard

✅ Ideal answer aria-label directly provides an accessible name as a string.

aria-labelledby references another element whose text provides the accessible name.
🔁 Follow-up: When would you prefer aria-labelledby? When there is already visible text that appropriately names the element.
🔁 Follow-up: Which should you prefer when visible text already exists? When appropriate, aria-labelledby can reference the visible label instead of duplicating the text in an aria-label.

💻 Code

index.html — Visual Studio Code
index.html
<!-- aria-label -->
<button aria-label="Close">×</button>

<!-- aria-labelledby -->
<h2 id="dialog-title">Delete Account</h2>
<div role="dialog" aria-labelledby="dialog-title"></div>

Q39 — What is the difference between autocomplete, placeholder, and value? Medium

✅ Ideal answer
  • placeholder provides a temporary hint.
  • value represents the actual current value.
  • autocomplete gives the browser information about the expected data type.
🔁 Follow-up: Should placeholder replace a label? No. It's not a proper replacement because it disappears when the user types.
🔁 Follow-up: What is the difference between autocomplete, autofocus, and placeholder? autocomplete controls whether/how the browser can use stored information to help fill a field.

autofocus requests that the element receive focus when the page/dialog is initially presented.

placeholder provides a short hint/example inside an empty input.

💻 Code

index.html — Visual Studio Code
index.html
<input
  type="email"
  name="email"
  autocomplete="email"
  placeholder="Enter your email"
  value="user@example.com">

Q40 — What is the difference between <ul>, <ol>, and <dl>? Easy

✅ Ideal answer
  • <ul> — unordered list.
  • <ol> — ordered list where sequence matters.
  • <dl> — description list (terms + descriptions).
🔁 Follow-up: Can CSS remove the bullets from a <ul>? Yes. Using list-style: none. But that doesn't change the semantic meaning.

💻 Code

index.html — Visual Studio Code
index.html
<ul> <li>Angular</li> <li>Spring Boot</li> </ul>

<ol> <li>Login</li> <li>Select</li> <li>Checkout</li> </ol>

<dl> <dt>Angular</dt> <dd>Frontend framework.</dd> </dl>
