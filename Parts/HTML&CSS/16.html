Q151 — What is CSS specificity, and how is it calculated? Medium

✅ Ideal answer Specificity is a mechanism used by the CSS cascade to determine which selector has higher priority when multiple selectors target the same element.

Hierarchy: Inline styles > IDs > Classes/Attributes/Pseudo-classes > Elements/Pseudo-elements.
🔁 Follow-up: Which is more specific? `#app .card p` or `.card p` #app .card p because it contains an ID in addition to the class and element selectors.

💻 Code

style.css — Visual Studio Code
style.css
p { color: blue; }           /* 0,0,1 */
.text { color: green; }      /* 0,1,0 */
#title { color: red; }       /* 1,0,0 ← Wins */

Q152 — Which is more specific: #id, .class, [attribute], :hover, or div? Medium

✅ Ideal answer Hierarchy: ID selector > Class / attribute / pseudo-class > Element / pseudo-element.

So #box > .box > div. And .box:hover has the specificity of one class plus one pseudo-class.
🔁 Follow-up: Does :hover have the same specificity as an element selector? No. :hover is a pseudo-class and has the same specificity category as a class selector.

💻 Code

style.css — Visual Studio Code
style.css
div { color: gray; }        /* Element */
.box { color: green; }      /* Class */
.box:hover { color: orange; } /* Class + Pseudo-class */
#box { color: red; }        /* ID ← Wins */

Q153 — What does !important do, and why should you avoid overusing it? Medium

✅ Ideal answer !important gives a declaration increased priority in the cascade.

Overusing it makes CSS harder to maintain because it makes normal overrides more difficult. I would first try to solve the problem using proper selectors, component styles, or better CSS architecture.
🔁 Follow-up: If two declarations both use !important, which one wins? The normal cascade rules still apply among declarations with comparable importance, including origin/layer and then specificity and source order.

💻 Code

style.css — Visual Studio Code
style.css
.btn { background: #3b82f6; }
.btn-danger { background: #ef4444 !important; } /* Overrides .btn */

Q154 — What is a CSS custom property? Easy → Medium

✅ Ideal answer A CSS custom property (CSS variable) is a user-defined property that can store a reusable value.

It helps with consistency, theming, and maintainability.
🔁 Follow-up: Where can you define custom properties? They can be defined on any element, and their values participate in CSS inheritance. For global variables, we commonly define them on :root.

💻 Code

style.css — Visual Studio Code
style.css
:root {
  --primary-color: #2563eb;
}

.button {
  background-color: var(--primary-color);
}

Q155 — What is the difference between CSS variables and Sass variables? Medium

✅ Ideal answer Sass variables (e.g., $primary: blue;) are processed by Sass during compilation.

CSS custom properties (e.g., --primary: blue;) exist in the browser at runtime.

CSS custom properties can be changed dynamically via JS and participate in inheritance and the cascade.
🔁 Follow-up: Can CSS custom properties be changed based on a class? Yes. For example, .dark { --primary: black; } will update components inside it.

💻 Code

style.css — Visual Studio Code
style.css
/* Sass (Compile time) */
$primary: blue;

/* CSS Custom Property (Runtime) */
:root { --primary: blue; }

.dark { --primary: black; }

Q156 — What is a stacking context, and how is it related to z-index? Hard

✅ Ideal answer A stacking context is a conceptual layering context in which elements are painted relative to each other.

z-index controls the stacking order of positioned elements within their relevant stacking context.

Properties that create a new stacking context include: opacity < 1, transform, isolation: isolate, and positioned elements with z-index.
🔁 Follow-up: Why doesn't increasing z-index: 999999 always put an element above everything? Because z-index is evaluated within stacking contexts. An element cannot simply escape its parent's stacking context to compete globally with another higher stacking context.

💻 Code

style.css — Visual Studio Code
style.css
.box-a { position: absolute; z-index: 2; }
.box-b { position: absolute; z-index: 1; } /* Behind box-a */

🔴 Live demo

Q157 — How can transform affect z-index or stacking behavior? Hard

✅ Ideal answer Applying a non-none transform (like transform: translateZ(0);) can create a new stacking context.

This can change how descendants participate in stacking relative to other elements. A child with a very high z-index may still appear underneath an element outside its parent's stacking context.
🔁 Follow-up: Can the child necessarily appear above an unrelated element with a lower z-index outside the parent's stacking context? No. The child's z-index is constrained by its parent's stacking context.

💻 Code

style.css — Visual Studio Code
style.css
.parent { transform: translateZ(0); z-index: 1; }
.child { z-index: 9999; } /* Trapped inside parent! */
.sibling { z-index: 2; }  /* Appears ABOVE the child */

🔴 Live demo

Child has z-index: 9999, but appears below the purple sibling because of the parent's transform!

Q158 — What is the difference between a CSS transition and a CSS animation? Easy → Medium

✅ Ideal answer A transition animates a property when it changes from one state to another (e.g., on hover).

An animation uses @keyframes and can define multiple stages. It can run without user interaction.
🔁 Follow-up: Can an animation run without user interaction? Yes. CSS animations can start automatically when the element is rendered.

💻 Code

style.css — Visual Studio Code
style.css
/* Transition */
.button { transition: background-color 0.3s ease; }
.button:hover { background-color: blue; }

/* Animation */
@keyframes bounce { 50% { transform: translateY(-30px); } }
.box { animation: bounce 1.5s infinite; }

Q159 — Why is transform: translate() often preferred over changing top or left for animations? Hard

✅ Ideal answer transform is preferable because it can avoid triggering layout recalculation (Reflow) that changing layout properties such as top or left may cause.

This results in smoother animations, especially when the browser can handle the transform efficiently during compositing.
🔁 Follow-up: Does using transform guarantee GPU acceleration? No. It's a common optimization-friendly property, but we shouldn't assume that every transform automatically guarantees better performance in every case.

💻 Code

style.css — Visual Studio Code
style.css
/* Smooth (No Reflow) */
.box { transition: transform 0.5s ease; }
.box:hover { transform: translateX(100px); }

/* Janky (Triggers Reflow) */
.box-bad { transition: left 0.5s ease; }
.box-bad:hover { left: 100px; }

Q160 — What is the difference between em, rem, %, vw, and vh? Medium

✅ Ideal answer
  • rem: Relative to the root element's font size.
  • em: Relative to the element's (or parent's) font size.
  • %: Relative to a containing/reference dimension.
  • vw: 1% of the viewport width.
  • vh: 1% of the viewport height.
🔁 Follow-up: Why do developers often prefer rem over px for typography? Because rem scales relative to the root font size and can make typography more adaptable and accessible, especially when users change their browser's default font size.

💻 Code

style.css — Visual Studio Code
style.css
html { font-size: 16px; }

.rem-box { font-size: 2rem; } /* 32px */
.em-box { font-size: 1.5em; }
.vw-box { font-size: 3vw; }
.vh-box { height: 20vh; }
