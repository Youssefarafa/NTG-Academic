Q101 — What is the difference between HTML parsing and DOM construction? Hard

✅ Ideal answer HTML parsing is the process where the browser reads the HTML source and interprets its tokens according to the HTML parsing algorithm.

During this process, the browser constructs the DOM (Document Object Model), which represents the document as a tree of nodes that JavaScript and other browser APIs can interact with.
🔁 Follow-up: Is the DOM the same thing as the original HTML source? No. The DOM is an in-memory representation of the document. JavaScript can modify the DOM after parsing, so the DOM can differ from the original HTML source.
🔁 Follow-up: Does the DOM exist in the HTML source code? No. The DOM is an in-memory object model created by the browser while parsing the document.
🔁 Follow-up: What is the difference between HTML and the DOM? HTML is the markup language used to describe the structure of a document.

The DOM (Document Object Model) is the browser's object representation of that document that JavaScript and other APIs can interact with.

The browser parses the HTML and creates a DOM tree conceptually like: 
Document
└── html
    └── body
        └── h1
            └── "Hello"
JavaScript can then interact with it:
document.querySelector("h1").textContent = "Hello Youssef";

Q102 — What happens if the browser encounters malformed HTML? Hard

✅ Ideal answer Browsers are designed to be fault-tolerant. They don't simply stop parsing when they encounter malformed HTML.

Instead, the HTML parsing algorithm has error-recovery rules that attempt to construct a valid DOM tree. Browsers can automatically close certain elements or restructure malformed markup according to the HTML parsing rules.
🔁 Follow-up: Does malformed HTML always produce the same DOM in every browser? Modern browsers generally follow the standardized HTML parsing algorithm, but relying on malformed markup is still bad practice because it makes behavior harder to reason about and maintain.

💻 Code

index.html — Visual Studio Code
index.html
<!-- Malformed: div inside p -->
<p>Hello <div>World</div></p>

<!-- Browser auto-corrects to: -->
<p>Hello </p>
<div>World</div>
<p></p>

Q103 — What is the DOM, and why is it important for JavaScript? Easy → Medium

✅ Ideal answer The DOM is an object-based representation of an HTML document.

JavaScript can use DOM APIs to: find elements, change content, modify attributes, change styles, create elements, remove elements, and respond to events.
🔁 Follow-up: Does changing the DOM automatically change the original HTML file? No. It changes the in-memory DOM for the current document. It doesn't modify the original HTML file on the server.

Q104 — What is event bubbling? Medium

✅ Ideal answer Event bubbling means that when an event occurs on an element, the event can propagate from that element upward through its ancestors.

Unless propagation is stopped, it goes from Target → Parent → Body → Document → Window.
🔁 Follow-up: How can you stop bubbling? Using event.stopPropagation(); This prevents the event from continuing to propagate through the relevant propagation path.

Q105 — What is event capturing? Medium → Hard

✅ Ideal answer Event capturing is the phase where an event travels from the outer ancestors toward the target element before reaching the target.

Propagation model: Window → Document → HTML → Body → Parent → Target.
🔁 Follow-up: Which phase does addEventListener('click', handler) use by default? The default is the bubbling phase. To use capturing, you pass true or { capture: true }.

Q106 — What is event delegation? Hard

✅ Ideal answer Event delegation is a technique where we attach a single event listener to a parent instead of attaching separate listeners to many child elements.

It relies on event bubbling. It's useful for dynamically added elements and reduces memory overhead.
🔁 Follow-up: What is the advantage? It can reduce the number of event listeners, simplify handling of dynamically added children, and reduce memory overhead in cases with many similar elements.

💻 Code

app.js — Visual Studio Code
app.js
products.addEventListener('click', (event) => {
  const item = event.target.closest('li');
  if (item) console.log(item.textContent);
});

Q107 — What is the difference between event.target and event.currentTarget? Hard

✅ Ideal answer event.target is the element where the event originally occurred.

event.currentTarget is the element whose event listener is currently executing.
🔁 Follow-up: Why is this important in event delegation? Because the listener is attached to the parent, but the event may originate from different children. event.target tells us which descendant initiated the event, while currentTarget tells us which element owns the listener.

💻 Code

app.js — Visual Studio Code
app.js
parent.addEventListener('click', (event) => {
  console.log(event.target);        // button
  console.log(event.currentTarget); // div
});

Q108 — What is the difference between preventDefault() and stopPropagation()? Medium → Hard

✅ Ideal answer preventDefault() prevents the browser's default behavior associated with an event (e.g., preventing form submission or link navigation).

stopPropagation() prevents the event from continuing through the propagation path (bubbling/capturing).
🔁 Follow-up: Can you use both at the same time? Yes. They control different aspects of event behavior.

💻 Code

app.js — Visual Studio Code
app.js
form.addEventListener('submit', (event) => {
  event.preventDefault(); // Stops browser from refreshing page
});

Q109 — What is Shadow DOM? Hard

✅ Ideal answer Shadow DOM is a web platform feature that allows an element to have an encapsulated DOM subtree.

It provides a boundary between the component's internal DOM and the surrounding document. This allows components to encapsulate their internal structure and styles.
🔁 Follow-up: Can styles from the outside freely affect elements inside a Shadow DOM? No. Shadow DOM provides style encapsulation boundaries, although there are specific mechanisms for styling or exposing parts of shadow content.

💻 Code

app.js — Visual Studio Code
app.js
const host = document.querySelector('.shadow-host');
const shadowRoot = host.attachShadow({ mode: 'open' });

shadowRoot.innerHTML = `
  <style>
    button { background: green; color: white; }
  </style>
  <button>Shadow Button</button>
`;

Q110 — What is Web Accessibility, and how would you make an HTML page accessible? Hard

✅ Ideal answer Web accessibility means designing and developing websites so that people with different abilities can use them effectively, including people who rely on keyboards, screen readers, or other assistive technologies.

Key areas: Semantic HTML, proper labels, keyboard accessibility, meaningful alt text, good focus management, ARIA when necessary, and sufficient color contrast.
🔁 Follow-up: Should you use ARIA everywhere? No. Native semantic HTML should be preferred whenever possible. A native <button> is preferable to <div role="button">.
