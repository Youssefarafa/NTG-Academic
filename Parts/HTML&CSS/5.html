Q41 — What is the difference between an HTML element and an HTML attribute? Easy

✅ Ideal answer An HTML element is a complete building block of the document, such as <p>, <div>, or <input>.
An attribute provides additional information or configuration about an element.

For example: <input type="email" id="email" required>
Here, <input> is the element, while type, id, and required are attributes.
🔁 Follow-up: Are all HTML elements allowed to have the same attributes? No. Some attributes are global and can be used on many elements, such as id, class, and title, while others are specific to particular elements, such as src for images.

Q42 — What are global HTML attributes? Easy → Medium

✅ Ideal answer Global attributes are attributes that can generally be used on most HTML elements.
Examples include: id, class, title, style, hidden, tabindex, data-*, and aria-*.

For example: <div id="profile" class="card" title="User profile">
🔁 Follow-up: What are data-* attributes? They allow developers to store custom data associated with an HTML element. For example, <button data-user-id="123">Delete</button>. JavaScript can access it through the element's dataset.

Q43 — What is the difference between data-* attributes and normal attributes? Easy → Medium

✅ Ideal answer data-* attributes are specifically intended for storing custom data on HTML elements without creating non-standard HTML attributes.

For example: <div data-product-id="25" data-category="plants">
In JavaScript: element.dataset.productId would access the data-product-id value.
🔁 Follow-up: Should sensitive information be stored in data-* attributes? No. Anything in the HTML is accessible to the client and should be treated as public. Sensitive information such as passwords or secret tokens should never be exposed there.

💻 Code

index.html — Visual Studio Code
index.html
<button id="deleteBtn" data-user-id="123" data-action="delete">
  Delete User
</button>

<script>
  const btn = document.getElementById('deleteBtn');
  btn.addEventListener('click', () => {
    console.log(btn.dataset.userId); // "123"
    console.log(btn.dataset.action); // "delete"
  });
</script>

Q44 — What is the difference between absolute, relative, fixed, and sticky positioning? Medium

✅ Ideal answer
  • relative: the element remains in the normal document flow but can be visually offset; it can also establish a containing block for positioned descendants.
  • absolute: the element is removed from normal flow and is positioned relative to its containing block.
  • fixed: the element is removed from normal flow and is positioned relative to the viewport in typical cases.
  • sticky: the element behaves like relatively positioned content until a threshold is reached, then sticks within its scrolling container.
🔁 Follow-up: Relative to what is an absolutely positioned element positioned? Usually to its nearest ancestor that establishes a positioning context, commonly an ancestor with position: relative, absolute, fixed, or sticky. If there isn't one, the containing block can be the initial containing block.

💻 Code

.relative-box { position: relative; top: 10px; left: 20px; }
.absolute-box { position: absolute; bottom: 10px; right: 10px; }
.fixed-box { position: fixed; bottom: 20px; right: 20px; }
.sticky-header { position: sticky; top: 0; }

Q45 — What is the difference between <script>, <script async>, and <script defer>? Medium

✅ Ideal answer A normal <script> can block HTML parsing while the browser fetches and executes the script.

With async, the script downloads in parallel with HTML parsing and executes as soon as it's available. Therefore, execution order between async scripts isn't guaranteed.

With defer, the script also downloads in parallel, but execution happens after HTML parsing is complete, and deferred scripts maintain their document order.
🔁 Follow-up: Which one is usually appropriate for scripts that depend on the DOM? defer is usually a good choice because the script executes after the HTML has been parsed.

Q46 — What is the difference between <link> and <a>? Easy → Medium

✅ Ideal answer <a> creates a hyperlink that users can interact with to navigate to another resource.

<link> defines a relationship between the current document and an external resource. It's commonly used in the <head> to load stylesheets.

For example: <link rel="stylesheet" href="styles.css"> while <a href="/about">About Us</a> is navigation.
🔁 Follow-up: Can <link> be placed inside <body>? Some link relationships have specific placement rules, but stylesheet links are conventionally placed in the <head>. The key distinction is that <link> is metadata/resource relationship, while <a> is an interactive hyperlink.

💻 Code

  <!-- link: loads a resource (invisible to user) -->
  <link rel="stylesheet" href="styles.css">
</head>
<body>
  <!-- a: user can click to navigate -->
  <a href="https://example.com">Go to Example</a>
</body>

Q47 — What is the difference between required, disabled, and readonly? Medium

✅ Ideal answer
  • required means the user must provide a value for the field for form validation to succeed.
  • disabled means the control is disabled and cannot normally be interacted with; disabled form controls are generally excluded from native form submission.
  • readonly means the user cannot modify the value, but the control remains generally usable and its value can be submitted.
🔁 Follow-up: If I have a disabled input, can JavaScript read its value? Yes. Disabling the input doesn't erase its value. JavaScript can still access the element and its value.

💻 Code

index.html — Visual Studio Code
index.html
<input name="email" required>
<input name="userId" value="123" readonly>
<input name="status" value="active" disabled>

Q48 — What is the difference between hidden and display: none? Medium

✅ Ideal answer The hidden HTML attribute indicates that an element is not currently relevant to the user and the browser normally doesn't render it.

display: none is a CSS rule that removes the element from the rendered layout.

Both normally result in the element not being visually rendered, but they communicate different intent: hidden is an HTML semantic state, while display: none is presentation.
🔁 Follow-up: Does display: none take space in the layout? No. The element doesn't occupy layout space.

Q49 — What is the difference between visibility: hidden and display: none? Medium

✅ Ideal answer display: none removes the element from the layout, so it doesn't occupy space.

visibility: hidden makes the element invisible, but it normally remains in the layout and keeps its space.

For example: display: none means the element doesn't participate in layout, while visibility: hidden keeps its layout space.
🔁 Follow-up: What about opacity: 0? opacity: 0 makes the element fully transparent, but the element can still occupy layout space and can potentially remain interactive depending on the situation.

💻 Code

Q50 — What is the difference between <iframe> and <embed>? Medium

✅ Ideal answer <iframe> embeds another HTML browsing context inside the current page. It's commonly used for embedding external pages, maps, videos, or other web content.

<embed> is a more general element for embedding external content, historically including plugins and certain document/media formats.

For modern web applications, <iframe> is much more commonly encountered for embedding another web page or external browsing context.
🔁 Follow-up: What security attribute can restrict an iframe? sandbox.
For example:
<iframe src="..." sandbox title="Embedded content"></iframe>

Sandboxing restricts capabilities of the embedded document unless specific permissions are explicitly enabled.
🔁 Follow-up: Can an iframe communicate with its parent page? Yes. JavaScript can communicate between windows/frames using mechanisms such as postMessage, especially when dealing with cross-origin contexts.
🔁 Follow-up: What is iframe sandbox and why is it useful? The sandbox attribute applies restrictions to content loaded inside an iframe.

With a sandbox, various capabilities are restricted by default. Specific capabilities can be selectively enabled using tokens.

For example, sandbox="allow-scripts" allows scripts while retaining other sandbox restrictions.

Possible tokens include: allow-scripts, allow-forms, allow-modals, allow-popups, allow-downloads, allow-same-origin, among others.
🔁 Follow-up: Is sandbox="allow-scripts" the same as allowing everything? No. It enables scripts but keeps other sandbox restrictions unless they are separately allowed. For example, alert() and confirm() additionally require allow-modals.

💻 Code

  src="/embedded-app"

  title="Embedded application"
></iframe>
