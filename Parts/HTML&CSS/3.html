Q21 — What is the difference between <section> and <article>? Easy → Medium

✅ Ideal answer <section> represents a thematic grouping of content within a page, while <article> represents a self-contained piece of content that could potentially stand on its own or be distributed independently.

For example, a blog page could have multiple <article> elements, while <section> could group related content such as "Latest Posts" or "Contact Information".
🔁 Follow-up: Can an <article> contain a <section>? Yes. An article can contain sections when the article itself has multiple thematic parts.

💻 Code

index.html — Visual Studio Code
index.html
<!-- section = thematic grouping (Latest Posts) -->
<section>
  <h2>Latest Posts</h2>
  <article><h3>Post 1</h3><p>…</p></article>
  <article><h3>Post 2</h3><p>…</p></article>
</section>

<!-- article can contain sections (self-contained, with parts) -->
<article>
  <h2>Standalone Article</h2>
  <section><h3>Part 1</h3><p>…</p></section>
  <section><h3>Part 2</h3><p>…</p></section>
</article>

<!-- section = thematic grouping (Contact) -->
<section>
  <h2>Contact Information</h2>
  <p>…</p>
</section>

Q22 — What is the difference between <strong> and <b>? Easy

✅ Ideal answer <strong> gives semantic importance to its content, while <b> mainly indicates that the text should be stylistically distinguished without adding the same semantic importance.

For example:
<strong>Warning:</strong> Your account will expire.
Here, "Warning" has semantic importance.
🔁 Follow-up: Does <strong> necessarily make text bold? Browsers usually render it as bold by default, but its important part is the semantic meaning, not the visual appearance. CSS controls the actual presentation.

💻 Code

index.html — Visual Studio Code
index.html
<!-- strong = semantic importance -->
<p><strong>Warning:</strong> Your account will expire.</p>

<!-- b = stylistic offset (no extra importance) -->
<p><b>Note:</b> This is just styled text, no extra importance.</p>

🔴 Live demo

Warning: Your account will expire.

Note: This is just styled text, no extra importance.

👀 Both look bold — but only <strong> tells screen readers "this is important".

Q23 — What is the difference between <em> and <i>? Easy

✅ Ideal answer <em> represents emphasized content semantically, while <i> represents text that is stylistically offset from the surrounding content without necessarily indicating emphasis.

For example, <em> can indicate that a word should be emphasized when the sentence is read.
🔁 Follow-up: Are <em> and <i> always displayed differently? By default, browsers commonly render both as italic, but their semantic meanings are different.

💻 Code

index.html — Visual Studio Code
index.html
<!-- em = emphasized meaning -->
<p>I <em>really</em> mean it.</p>

<!-- i = stylistically offset (e.g. technical term, foreign word) -->
<p>This is the <i>scientific name</i> of the species.</p>

Q24 — Why should we use <button> instead of a clickable <div>? Easy → Medium

✅ Ideal answer A <button> is designed specifically for user actions. It provides built-in keyboard accessibility, focus behavior, semantics for assistive technologies, and standard browser behavior.
A <div> is only a generic container — making it clickable means manually reproducing keyboard interaction and accessibility semantics.
🔁 Follow-up: What if the clickable element navigates to another page? I would generally use an <a> element because navigation is the semantic purpose of a link.

💻 Code

index.html — Visual Studio Code
index.html
<!-- ❌ clickable div: NOT keyboard focusable by default -->
<div class="fake-button"
     onclick="document.getElementById('q14-output').textContent='Div clicked by mouse. Can you Tab to it? No.';">
  Click me (div)
</div>

<!-- ✅ real button: focusable, Enter/Space activate it, screen-reader friendly -->
<button type="button"
        onclick="document.getElementById('q14-output').textContent='Button clicked! Try Tab + Enter too.';">
  Click me (button)
</button>

<p id="q14-output">Click either element. Then try Tab — only the button gets focus.</p>

Q25 — What is the difference between <a> and <button>? Easy → Medium

✅ Ideal answer An <a> is primarily used for navigation to another URL or resource, while a <button> is used to perform an action.

For example:
<a href="/profile">Profile</a> → navigation.
<button type="button">Open Modal</button> → action.
🔁 Follow-up: What would you use for a "Delete Account" action? A <button>, because deleting is an action, not navigation.

💻 Code

index.html — Visual Studio Code
index.html
<!-- ✅ Navigation → <a> -->
<a href="#q15-profile">Go to Profile</a>

<!-- ✅ Action → <button> -->
<button type="button"
        onclick="document.getElementById('q15-modal').style.display='block';">
  Open Modal
</button>

<p id="q15-profile">📍 Profile page — the link navigated you here.</p>
<p id="q15-modal" style="display:none;">🪟 Modal opened — this is an action, not navigation.</p>

Q26 — What is the purpose of the alt attribute in an <img>? Easy

✅ Ideal answer The alt attribute provides alternative text describing the image. It's used by screen readers and is displayed when the image cannot be loaded.
For meaningful images, alt should describe their purpose or content.
For purely decorative images, alt can be empty: <img src="decoration.png" alt="">
🔁 Follow-up: Should we put "image of..." in every alt? Not necessarily. Screen readers already announce it's an image — the alt text should focus on useful information, not "image of".
🔁 Follow-up: What should you use for a purely decorative image? Usually an empty alt: <img src="decoration.png" alt="">
This tells assistive technologies that the image is decorative and can be ignored.

💻 Code

index.html — Visual Studio Code
index.html
<!-- meaningful image → describe its purpose -->
<img src="circle.svg" alt="Company logo">

<!-- decorative image → empty alt (screen readers skip it) -->
<img src="pattern.svg" alt="">

<!-- broken image → alt text is displayed as fallback -->
<img src="missing.png" alt="A red circle icon">

Q27 — What is the difference between id, class, and name attributes? Medium

✅ Ideal answer
  • id — identifies an element uniquely within the document.
  • class — groups elements for styling or JavaScript behavior.
  • name — identifies a form control when its value is submitted as part of form data.

<input id="email" name="email" class="form-control" type="email">
Here: id associates with a <label>, class is for styling, name is the key used when submitting form data.
🔁 Follow-up: Why do we usually connect <label> to the input using for and id? It associates the label with the input, improving accessibility and allowing users to focus the input by clicking the label.
🔁 Follow-up: What happens if an input has no name? Its value generally won't be included as a successful form control during native form submission.
🔁 Follow-up: What is the difference between id and name on an <input>? id uniquely identifies an element within the document and can be used by <label for="">, CSS, JavaScript, fragment URLs, etc.

name identifies the form field's name when the form is submitted.

id → DOM/document identity
name → form submission identity
🔁 Follow-up: Can id and name have the same value? Yes. That's actually common, as long as the id is unique within the document.

💻 Code

index.html — Visual Studio Code
index.html
<form id="q17Form">
  <label for="email">Email</label>
  <input id="email" name="email" class="form-control" type="email" value="user@example.com">
  <button type="submit">Submit</button>
</form>
<div id="q17Result">Click Submit to see what gets sent to the server.</div>

<script>
  document.getElementById('q17Form').addEventListener('submit', e => {
    e.preventDefault();
    const params = new URLSearchParams(new FormData(e.target));
    document.getElementById('q17Result').textContent =
      'Submitted: ' + params.toString();
  });
</script>

Q28 — What is the purpose of the <label> element? Easy

✅ Ideal answer <label> provides a textual description for a form control and improves accessibility.
It can be associated with an input using for: <label for="email">Email</label><input id="email" type="email">
Clicking the label will also focus or activate the associated control.
🔁 Follow-up: Can we wrap the input inside the label? Yes. <label>Email <input type="email"></label> creates an implicit association between the label and the input.
🔁 Follow-up: What is the difference between <label> and placeholder? A <label> provides a persistent accessible name for a form control.

<label for="email">Email address</label>
<input id="email" type="email">

A placeholder is temporary hint text shown inside the control:

<input type="email" placeholder="you@example.com">

A placeholder should not replace a proper label because it disappears when the user enters a value and can create usability and accessibility problems.
🔁 Follow-up: What happens when the user clicks the label? The associated form control receives focus, assuming the association is correct.
🔁 Follow-up: How do you associate a <label> with an <input>? Ideal answer:
There are two common approaches.

Using for + id:
<label for="username">Username</label>
<input id="username" name="username">

The for value must match the input's id.

Or nesting:
<label>
  Username
  <input name="username">
</label>

Both create an explicit relationship between the label and control.

🔁 Follow-up: Why is this important?
It improves accessibility and makes the label clickable, which also improves usability.

💻 Code

index.html — Visual Studio Code
index.html
<!-- Explicit: for + id -->
<label for="q18-email">Email (explicit for/id)</label>
<input id="q18-email" type="email" placeholder="Click the label → input focuses">

<!-- Implicit: input wrapped inside label -->
<label class="inline-label">
  Email (implicit — input inside label)
  <input type="email" placeholder="Click here → input focuses">
</label>

🔴 Live demo — click the labels

👀 Click either label text — the input focuses. That's accessibility for free.

Q29 — What is the difference between GET and POST when submitting an HTML form? Medium

✅ Ideal answer With a traditional HTML form:
  • GET — sends form data as part of the URL query string.
  • POST — sends the data in the request body.
GET is commonly used for retrieving/searching data; POST is used for submitting data that causes a server-side operation.
🔁 Follow-up: Is POST automatically secure? No. POST does not provide encryption by itself. HTTPS is what encrypts the communication between the client and server.

💻 Code

index.html — Visual Studio Code
index.html
<!-- GET → data goes in the URL: /search?search=laptop -->
<form id="q19GetForm" method="GET">
  <input name="search" value="laptop">
  <button type="submit">Submit GET</button>
</form>

<!-- POST → data goes in the request body -->
<form id="q19PostForm" method="POST">
  <input name="username" value="Youssef">
  <input name="email" value="y@example.com">
  <button type="submit">Submit POST</button>
</form>

<script>
  document.getElementById('q19GetForm').addEventListener('submit', e => {
    e.preventDefault();
    const params = new URLSearchParams(new FormData(e.target));
    document.getElementById('q19GetResult').textContent =
      'GET → /search?' + params.toString();
  });
  document.getElementById('q19PostForm').addEventListener('submit', e => {
    e.preventDefault();
    const params = new URLSearchParams(new FormData(e.target));
    document.getElementById('q19PostResult').textContent =
      'POST → body: ' + params.toString();
  });
</script>

Q30 — What is the difference between disabled and readonly on an input? Medium

✅ Ideal answer disabled — the control cannot be interacted with and is generally excluded from form submission.
readonly — the user cannot modify the value, but the control can still be focused and its value can participate in form submission.
🔁 Follow-up: Can JavaScript change a readonly input? Yes. readonly prevents the user from editing through the UI, but JavaScript can still modify its value.
🔁 Follow-up: Can readonly be used on every input type? No. readonly applies to specific form control types, primarily text-like inputs and <textarea>. It doesn't apply meaningfully to controls such as checkbox / radio in the same way.

💻 Code

index.html — Visual Studio Code
index.html
<label for="roInput">readonly</label>
<input id="roInput" type="text" value="Youssef" readonly>

<label for="disInput">disabled</label>
<input id="disInput" type="text" value="Youssef" disabled>

<button type="button" onclick="q20ChangeBoth()">🔄 Change both via JS</button>
<button type="button" onclick="q20ShowSubmit()">📤 Simulate form submit</button>

<div id="q20Result">Click "Simulate form submit"…</div>

<script>
  function q20ChangeBoth() {
    document.getElementById('roInput').value  = 'Ahmed (via JS)';
    document.getElementById('disInput').value = 'Ahmed (via JS)';
  }
  function q20ShowSubmit() {
    const ro  = document.getElementById('roInput').value;
    const dis = document.getElementById('disInput').value;
    document.getElementById('q20Result').textContent =
      'Form submission values:\n' +
      '  readonly → "' + ro  + '"  ✅ included\n' +
      '  disabled → "' + dis + '"  ❌ excluded';
  }
</script>
