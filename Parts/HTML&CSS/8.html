Q71 — What is the difference between <blockquote> and <q>? Easy → Medium

✅ Ideal answer Both <blockquote> and <q> are semantic elements for quotations, but they serve different purposes:

  • <blockquote> is a block-level element for long, multi-line quotes that should stand apart from the surrounding text. It does not add quotation marks by default.
  • <q> is an inline element for short quotes inside a paragraph. Browsers automatically wrap it in language-appropriate quotation marks (controlled by the quotes CSS property and the ::before / ::after pseudo-elements).
Both accept the cite attribute (a URL pointing to the source), but it is metadata only — it renders nothing and does not make the element a link.

For the visible source text, use a nested <cite> (often inside a <footer> within the <blockquote>).
🔁 Follow-up: Should I use <blockquote> for pull quotes? No. A pull quote is a visual design element, not a quotation from another source. Use a <div> or <aside> styled with CSS instead — reserving <blockquote> for actual quoted content keeps the document semantics honest.
🔁 Follow-up: Does the cite attribute on <blockquote> do anything? No visual effect. cite is intended for machines (search engines, screen readers, scrapers). To make the source clickable for users, add an explicit <a> or <cite> inside the quote.

    <footer>— <cite>Arthur C. Clarke</cite></footer>
</blockquote>

Q72 — What is the purpose of the <time> element, and why does it need a datetime attribute? Medium

✅ Ideal answer <time> is a semantic inline element that marks a specific date or time. Browsers render it exactly like plain text — no default styling — but the element makes the value machine-readable.

The datetime attribute supplies the machine-readable version when the visible text is human-friendly but ambiguous:
<time datetime="2025-10-25T14:00">tomorrow at 2pm</time>

If the visible text is already in a valid machine-readable format (YYYY-MM-DD, HH:MM, YYYY-MM-DDTHH:MM, etc.), datetime can be omitted.

The value is consumed by search engines (for rich results), calendar apps, screen readers, and feeds — none of which can interpret "tomorrow at 2pm" on their own.
🔁 Follow-up: Do search engines actually use the datetime value? Yes. Google uses <time> markup (often combined with schema.org datePublished / dateModified) to display publish dates in rich results and to order articles in search.
🔁 Follow-up: Can I omit the datetime attribute? Only if the visible text is already a valid machine-readable format. <time>2025-10-20</time> is fine. But <time>Christmas Day</time> is invalid — you must add datetime="2025-12-25".

💻 Code

index.html — Visual Studio Code
index.html
<!-- Human-friendly text, precise machine value -->

<!-- Readable text + timezone-aware datetime -->
<p>Meeting: <time datetime="2025-10-25T14:00">tomorrow at 2pm</time></p>

<!-- Visible text is already machine-readable → datetime can be omitted -->
<p>Posted: <time>2025-10-20</time></p>

Q73 — What is the difference between <figure> and <img>? Easy → Medium

✅ Ideal answer <img> represents an image.

<figure> is a semantic container for self-contained content such as an image, diagram, code example, or illustration, optionally accompanied by a <figcaption>.
🔁 Follow-up: Is <figure> only for images? No. It can represent other self-contained content, such as diagrams, charts, code snippets, or illustrations.

Q75 — What is the difference between <video> and <audio>? Easy

✅ Ideal answer <video> is used to embed video content, while <audio> is used for audio content.

Both support common attributes such as controls, autoplay, loop, muted, and preload.
🔁 Follow-up: Why might autoplay fail even if I specify autoplay? Modern browsers often restrict autoplay when media contains audio or isn't considered user-initiated. Muted autoplay is more commonly allowed.
🔁 Follow-up: What are the controls, autoplay, muted, and loop attributes? controls: shows native playback controls.
<video controls>

autoplay: requests automatic playback.
<video autoplay>

muted: starts the media muted.
<video autoplay muted>

loop: repeats the media.
<video loop>

These are boolean HTML attributes.

  <source src="audio.mp3" type="audio/mpeg">

Q76 — What is the purpose of the <source> element? Medium

✅ Ideal answer <source> specifies alternative media resources for elements such as <video> and <audio>.

The browser can choose a supported source format.
🔁 Follow-up: What happens if none of the sources are supported? The browser won't be able to play the media, and fallback content placed inside the <video> or <audio> element can be displayed.

💻 Code

index.html
<video controls>
  <source src="video.webm" type="video/webm">
  <source src="video.mp4" type="video/mp4">
  Your browser does not support HTML video.
</video>

Q77 — What is the difference between <canvas> and <svg>? Medium → Hard

✅ Ideal answer <canvas> provides a bitmap drawing surface that JavaScript can manipulate, while SVG is a vector-based markup format where graphical elements are represented as DOM nodes.

Canvas is often useful for games, image processing, and dynamic drawings. SVG is useful for scalable graphics, icons, diagrams, and accessible DOM elements.
🔁 Follow-up: Which one scales without losing quality? SVG is vector-based, so it scales without pixelation.
🔁 Follow-up 2: Can I style SVG elements with CSS? Yes. SVG elements can often be styled and manipulated using CSS and JavaScript.

styles.css
/* Smooth scaling when we later change width/height via JS */
#q77-canvas,
#q77-svg {
  display: block;
  transition: width 0.4s ease, height 0.4s ease;
  border-radius: 6px;
}

/* SVG circle is a real DOM node — CSS targets it directly */
#q77-svg circle {
  cursor: pointer;
  transition: fill 0.25s ease;
}

#q77-svg circle:hover {
  fill: #0ca678; /* turns green on hover */
}

/* Canvas has no per-pixel node — only the whole element is stylable */
#q77-canvas:hover {
  outline: 2px dashed #3b5bdb;
}
script.js — Visual Studio Code
script.js
const canvas  = document.getElementById('q77-canvas');
const svg     = document.getElementById('q77-svg');
const zoomBtn = document.getElementById('q77-zoom');
const status  = document.getElementById('q77-status');

// 1) Draw the same shape on canvas — pixels only, no DOM node for the circle
const ctx = canvas.getContext('2d');
ctx.fillStyle = '#3b5bdb';
ctx.beginPath();
ctx.arc(50, 50, 40, 0, Math.PI * 2);
ctx.fill();
ctx.fillStyle = '#fff';
ctx.font = 'bold 13px sans-serif';
ctx.textAlign = 'center';
ctx.textBaseline = 'middle';
ctx.fillText('Canvas', 50, 50);

// 2) SVG circle is a real DOM node — JS can attach events to it
svg.querySelector('circle').addEventListener('click', function () {
  status.textContent = 'SVG circle clicked — it is a real DOM node with an event listener.';
});

// 3) Zoom both by changing CSS width/height.
//    Canvas: stretches its 100×100 bitmap  → blurry / pixelated
//    SVG:    re-renders its vectors from viewBox  → stays crisp
let zoomed = false;
zoomBtn.addEventListener('click', function () {
  zoomed = !zoomed;
  const size = zoomed ? '300px' : '100px';
  canvas.style.width  = size;
  canvas.style.height = size;
  svg.style.width     = size;
  svg.style.height    = size;

  zoomBtn.textContent = zoomed ? 'Reset' : 'Zoom 3×';
  status.textContent = zoomed
    ? 'Zoomed 3×: canvas is pixelated (bitmap stretched), SVG is crisp (vector re-rendered).'
    : 'Reset. Hover the SVG circle — it turns green. The canvas cannot respond per-shape.';
});

Q78 — What is the difference between <template> and normal HTML elements? Hard

✅ Ideal answer The <template> element contains HTML that isn't rendered as part of the document immediately.

Its content is stored as a DocumentFragment and can later be cloned and inserted into the DOM using JavaScript.
🔁 Follow-up: Is the content inside <template> immediately visible? No. It's inert until it is explicitly cloned and inserted into the document.
🔁 Follow-up 2: What is the difference between using <template> and building HTML with a backtick string + innerHTML? Both work, but they differ in parsing, safety, and how you bind events:

🆚 Comparison — <template> + cloneNode vs Backtick + innerHTML

<template> + cloneNode Backtick string + innerHTML
Parsing Parsed once, cloned many times String re-parsed on every insertion
When it exists In the DOM from the start, but inert (not rendered, scripts don't run, images don't load) Nothing exists until the string is injected — then everything fires immediately
Safety Safe by default — fill placeholders with textContent XSS risk if you interpolate untrusted data
Event handlers Attach directly to the cloned node Must re-query after insertion or use event delegation
Element refs Available via .content.querySelector() before cloning Only after insertion
Best for Repeated list items, Web Components, big batches One-off HTML, quick prototyping

💻 Code

index.html — Visual Studio Code
index.html
<!-- The reusable template (hidden by default) -->
<template id="user-card">
  <div class="user-card">
    <h3>User Name</h3>
    <button class="remove-btn">×</button>
  </div>
</template>

<!-- Two containers to compare the two approaches -->

approach-a.js — <template> + cloneNode
approach-a.js
const tpl = document.getElementById('user-card');
const out = document.getElementById('out-template');

function addCard(name) {
  // 1. Clone the pre-parsed fragment — fast, no re-parsing
  const clone = tpl.content.cloneNode(true);

  // 2. Fill placeholders safely with textContent (no XSS)
  clone.querySelector('h3').textContent = name;

  // 3. Attach event listeners directly on the cloned node
  clone.querySelector('.remove-btn').addEventListener('click', e => {
    e.currentTarget.closest('.user-card').remove();
  });

  // 4. Insert
  out.appendChild(clone);
}
approach-b.js — Backtick + innerHTML
approach-b.js
const out2 = document.getElementById('out-innerhtml');

function addCardHTML(name) {
  // ⚠️ If `name` comes from user input, this is an XSS hole.
  //    Escape it (or use textContent) before interpolating.
  out2.insertAdjacentHTML('beforeend', `
    <div class="user-card">
      <h3>${name}</h3>
      <button class="remove-btn">×</button>
    </div>
  `);
}

// Handlers can't be attached to nodes that don't exist yet,
// so use event delegation on the container instead:
out2.addEventListener('click', e => {
  if (e.target.classList.contains('remove-btn')) {
    e.target.closest('.user-card').remove();
  }
});

Q79 — What is the contenteditable attribute? Medium

✅ Ideal answer contenteditable makes an element's content editable by the user.

The user can modify the content directly in the browser.
🔁 Follow-up: Would you trust the content entered through contenteditable and send it directly to the backend? No. User-generated content must be treated as untrusted. If it's stored or rendered as HTML, it needs appropriate validation/sanitization and safe handling to avoid issues such as XSS.

Q80 — What is the tabindex attribute and why is it important? Medium → Hard

✅ Ideal answer tabindex controls whether an element can receive keyboard focus and, in some cases, its position in the sequential keyboard navigation order.

A value of 0 allows an element to participate in the natural tab order.
A negative value such as -1 allows programmatic focus but removes the element from sequential keyboard navigation.
🔁 Follow-up: Should we use positive tabindex values like tabindex="1"? Generally no. Positive tabindex values create a custom tab order that can become difficult to maintain and can harm keyboard accessibility. It's usually better to rely on the natural document order.

💻 Code

index.html
<button tabindex="0">Focusable in natural order</button>
