Q81 — What is the difference between autocomplete="on" and specific autocomplete tokens? Medium

✅ Ideal answer autocomplete="on" allows the browser to use its general autofill behavior.

Specific autocomplete tokens give the browser more precise information about what kind of data the field represents (e.g., email, given-name, new-password).

This can improve autofill accuracy and accessibility.
🔁 Follow-up: Why is autocomplete="new-password" useful? It tells the browser that the field is intended for a new password rather than an existing login password, which can help password managers and autofill systems behave appropriately.
🔁 Follow-up: What is the difference between autocomplete="off" and disabling browser autofill? autocomplete is a browser hint describing whether and how the browser should use previously stored information to assist with form filling.

For example: <input type="text" name="username" autocomplete="username">

You can also specify autocomplete="off" to request that autocomplete not be used.

However, autocomplete="off" is not an absolute guarantee that the browser will never provide autofill or password-management behavior. Browsers and password managers can make their own decisions, particularly for credentials.
🔁 Follow-up: How would you improve autocomplete for a login form? 
<input type="text" name="username" autocomplete="username">

<input type="password" name="password" autocomplete="current-password">
For account creation, a new password can use autocomplete="new-password".

💻 Code

index.html
<input type="email" name="email" autocomplete="email">
<input type="password" name="pwd" autocomplete="new-password">

Q82 — What is the purpose of the accept attribute on <input type="file">? Easy

✅ Ideal answer The accept attribute provides a hint to the browser about the types of files the user should select.

It helps filter the file picker and communicate expected file types.
🔁 Follow-up: Does accept guarantee that the uploaded file is actually an image? No. It's only a client-side hint. The backend must validate the uploaded file independently, including its actual type and potentially its content.

💻 Code

index.html — Visual Studio Code
index.html
<input type="file" accept="image/*">
<input type="file" accept=".pdf,.doc,.docx">

Q83 — What is the difference between multipart/form-data and application/x-www-form-urlencoded? Hard

✅ Ideal answer application/x-www-form-urlencoded encodes form fields as key-value pairs in the request body using URL encoding.

multipart/form-data divides the request body into multiple parts, making it suitable for uploading files along with regular form fields.
🔁 Follow-up: Why wouldn't we normally send a file using JSON? JSON isn't designed to represent binary file data directly. We could encode a file as Base64, but that adds overhead. multipart/form-data is designed specifically for sending files and fields together.

Q84 — What is the difference between enctype="application/x-www-form-urlencoded" and enctype="multipart/form-data" in a form? Hard

✅ Ideal answer The enctype attribute determines how the browser encodes form data when submitting the form.

multipart/form-data is commonly used when the form contains file uploads.
For ordinary text form data, the default is generally application/x-www-form-urlencoded.
🔁 Follow-up: If a form contains an image upload, which enctype would you choose? multipart/form-data.
🔁 Follow-up: What is the purpose of enctype on a form? enctype specifies how form data is encoded when the browser submits a form using POST.

Common values include:
  • application/x-www-form-urlencoded (the default in most cases)
  • multipart/form-data
  • text/plain
For file uploads, we typically use multipart/form-data.
🔁 Follow-up: Why is multipart/form-data required for file uploads? It allows the request body to represent multiple parts, including binary file data and other form fields.
🔁 Follow-up: What happens if you forget enctype="multipart/form-data" on a file upload form? The browser sends the form as application/x-www-form-urlencoded, which means only the filename is submitted — the actual file bytes are not sent. The server won't receive the file, and the upload will fail silently. This is a very common bug.

💻 Code

index.html — Visual Studio Code
index.html
<!-- Text only -->
<form method="POST" enctype="application/x-www-form-urlencoded">

<!-- File upload -->
<form method="POST" enctype="multipart/form-data">
  <input type="file" name="avatar">
</form>

Q85 — What is the purpose of the novalidate attribute on a form? Medium

✅ Ideal answer novalidate tells the browser not to perform its built-in constraint validation when submitting the form.

This can be useful when an application wants to handle validation entirely through JavaScript or a framework.
🔁 Follow-up: Does novalidate remove Angular Reactive Forms validators? No. novalidate affects the browser's native HTML constraint validation. Angular's own validation system is separate and can still run.

💻 Code

index.html — Visual Studio Code
index.html
<form novalidate>
  <input type="email" required>
  <button type="submit">Submit</button>
</form>

Q86 — What is the difference between minlength and pattern? Easy → Medium

✅ Ideal answer minlength checks that the value contains at least a specified number of characters.

pattern uses a regular expression to define a required format.
🔁 Follow-up: Does minlength validate that a value exists? Not necessarily. If the field is optional, an empty value can be allowed. If I want to require a value, I should use required as well.
🔁 Follow-up: What is the difference between required, minlength, maxlength, min, and max? required → value must be provided

minlength → minimum number of characters
maxlength → maximum number of characters
min → minimum numeric/date/etc. value
max → maximum numeric/date/etc. value

These participate in the browser's constraint validation system.
🔁 Follow-up: Does HTML validation replace server-side validation? No. Client-side validation improves UX, but the server must validate incoming data because clients cannot be trusted.
🔁 Follow-up: What is the difference between pattern validation and JavaScript validation? The pattern attribute provides a declarative way to define a regular-expression constraint for certain text-based input types.

Example: <input type="text" name="username" pattern="[A-Za-z0-9_]{3,15}" required>

The browser can perform constraint validation before submitting the form.

JavaScript can implement more complex validation logic, for example when validation depends on application rules or asynchronous/server-side checks.

Native HTML validation is useful for straightforward constraints, while JavaScript is useful when validation depends on more complex application rules or asynchronous/server-side checks.
🔁 Follow-up: Does pattern validate the value on the server? No. It's client-side browser validation. The server must validate the data independently.

💻 Code

index.html — Visual Studio Code
index.html
<input minlength="8" placeholder="At least 8 chars">
<input pattern="[A-Za-z]+" placeholder="Letters only">

Q87 — What is the difference between min/max and minlength/maxlength? Easy → Medium

✅ Ideal answer min and max generally constrain the numerical value of an input.

minlength and maxlength constrain the number of characters in text-like input values.
🔁 Follow-up: What if I use min="8" on a text input? min isn't a general-purpose string-length validator. For text length, minlength is the appropriate constraint.

💻 Code

<input type="text" minlength="3" maxlength="20">

Q88 — What is the purpose of the loading attribute on images and iframes? Medium

✅ Ideal answer The loading attribute can provide a hint about when resources such as images or iframes should be loaded.

loading="lazy" tells the browser that the resource can be deferred until it is closer to the viewport.
loading="eager" indicates that the resource should be loaded without lazy-loading behavior.
🔁 Follow-up: Should every image use loading="lazy"? Not necessarily. Important above-the-fold images, especially key visual content such as a hero image or potentially an LCP image, may be better loaded eagerly.
🔁 Follow-up: What is the loading="lazy" attribute? loading="lazy" tells the browser that an image or iframe can be loaded lazily, meaning the browser may defer loading it until it is closer to the viewport.

Example:
<img src="plant.jpg" alt="Plant" loading="lazy">

This can reduce initial network work and improve initial page loading performance for pages containing many off-screen resources.

🔁 Follow-up: Should you lazy-load every image?
Not necessarily. Images that are immediately visible, especially important above-the-fold or LCP content, generally shouldn't blindly be lazy-loaded because delaying them can hurt perceived or measured performance.
🔁 Follow-up: A page contains 100 images. Would you add loading="lazy" to all of them? Not blindly.

For images far below the initial viewport, lazy loading can reduce unnecessary initial loading work:
<img src="plant.jpg" alt="Tomato plant" loading="lazy">

But I would generally avoid lazy-loading critical above-the-fold images because delaying them can hurt loading performance, especially the image contributing to LCP.

So I'd decide based on:
  • Position in the page
  • Importance of the image
  • Network cost
  • Expected user behavior
🔁 Follow-up: What about an image that's immediately visible at the top of the page? I generally wouldn't lazy-load a critical above-the-fold image unless there is a specific reason.

💻 Code

index.html — Visual Studio Code
index.html
<img src="hero.jpg" loading="eager" alt="Hero">
<img src="gallery-1.jpg" loading="lazy" alt="Gallery">

Q89 — What is the srcset attribute and why is it useful? Hard

✅ Ideal answer srcset allows us to provide multiple image resources so the browser can choose an appropriate one based on factors such as viewport size and device characteristics.

This can reduce unnecessary bandwidth usage and improve image performance.
🔁 Follow-up: What's the difference between srcset and sizes? srcset provides candidate image resources, while sizes gives the browser information about the expected rendered width of the image under different viewport conditions so it can choose an appropriate candidate.

💻 Code

index.html — Visual Studio Code
index.html
<img
  src="plant-800.jpg"
  srcset="
    plant-400.jpg 400w,
    plant-800.jpg 800w,
    plant-1200.jpg 1200w
  "
  sizes="(max-width: 600px) 400px, 800px"
  alt="Plant">

Q90 — What is the difference between srcset and <picture>? Hard

✅ Ideal answer srcset allows the browser to choose among different image candidates, usually based on resolution or rendered size.

<picture> provides more control over which image resource is selected, including using media conditions and different formats or art direction.

This can be useful when the mobile version needs a completely different crop or when we want to offer different formats.
🔁 Follow-up: When would you use <picture> instead of only srcset? I'd use <picture> when I need art direction, media-based source selection, or different image formats. If I only need different resolutions of essentially the same image, srcset is often sufficient.

💻 Code

index.html — Visual Studio Code
index.html
<picture>
  <source media="(max-width: 600px)" srcset="plant-mobile.jpg">
  <source type="image/webp" srcset="plant.webp">
  <img src="plant.jpg" alt="Plant">
</picture>
