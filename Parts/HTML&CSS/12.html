Q111 — What is CSS and what problem does it solve? Easy

✅ Ideal answer CSS stands for Cascading Style Sheets. It is used to control the presentation and layout of web documents.

HTML defines the structure and meaning of the content, while CSS controls things such as: colors, fonts, spacing, layout, responsive design, animations, and visual appearance.
🔁 Follow-up: Can we build a website without CSS? Yes. HTML can create the structure and content, but the page will rely mostly on the browser's default styles and won't have the intended visual design.

Q112 — What does "Cascading" mean in CSS? Easy → Medium

✅ Ideal answer The cascade is the process the browser uses to determine which CSS declarations should apply when multiple rules target the same element.

The result depends on factors such as: origin and importance, cascade layers, specificity, and source order.
🔁 Follow-up: Does the last CSS rule always win? No. Source order is only one factor. A more specific selector or a declaration with different cascade priority can win even if it appears earlier.

Q113 — What are the three main ways to apply CSS? Easy

✅ Ideal answer There are three common ways:
  1. Inline CSS: <p style="color: red;">
  2. Internal CSS: Using a <style> tag in the <head>.
  3. External CSS: Using a <link rel="stylesheet"> tag.
External stylesheets are generally preferred for maintainability and reuse.
🔁 Follow-up: Which approach is generally best for a large application? External stylesheets or a well-structured CSS architecture are generally preferable because they improve reuse, maintainability, and separation of concerns.

Q114 — What is a CSS selector? Easy

✅ Ideal answer A CSS selector identifies the elements to which a CSS rule applies.

CSS supports different types of selectors, including: element selectors, class selectors, ID selectors, attribute selectors, combinators, pseudo-classes, and pseudo-elements.
🔁 Follow-up: What does the selector .card p mean? It selects p elements that are descendants of an element with the class card.

Q115 — What is the * (universal) selector, when should you use it, and what is its most famous use case? Easy → Medium

✅ Ideal answer The * (universal) selector matches every element in the document — and every pseudo-element (::before, ::after) when written together as *, *::before, *::after.

Its specificity is 0,0,0 — the lowest possible — so any other selector (element, class, ID) overrides it. That's what makes it safe as a baseline: it sets defaults that you can always override with a more specific rule.

When to use it:
  • ✅ One global reset — box-sizing, margins, font inheritance, etc.
  • ✅ Debugging — * { outline: 1px solid red } to reveal every element's layout box.
  • ✅ Overriding user-agent defaults — zeroing padding on h1–h6, ul, body.
When NOT to use it:
  • ❌ For actual styling — * { color: red } is a maintenance nightmare. Use classes.
  • ❌ For hover/focus/animations — every element reacting at once is almost never what you want.
The most famous use case is the modern box-sizing reset: 
*, *::before, *::after {
  box-sizing: border-box;
}
This single rule makes every element's width include its padding and border — the behavior almost every developer expects. Tailwind, Bootstrap, and virtually every modern CSS framework starts with this exact line.
🔁 Follow-up: Does * override inherited styles? No — and that's the point. Inheritance and the universal selector are two different mechanisms. When you write * { color: red }, it doesn't "win" over an inherited value because there's no cascade competition — * directly targets every element. But because its specificity is 0,0,0, any explicit rule on a specific element (e.g. p { color: blue }) wins immediately. This is why * is perfect for resets: it sets a baseline that any specific rule can override.

Q116 — What is the difference between the descendant, child, adjacent sibling, and general sibling combinators? Medium

✅ Ideal answer CSS has four combinators that describe the relationship between the element on the left and the element on the right of the symbol:
Combinator Symbol Matches Example
Descendant   (space) Any element at any depth inside the ancestor .box p
Child > Only direct children .box > p
Adjacent sibling + The next sibling immediately after (same parent) .first + p
General sibling ~ All following siblings (same parent) .first ~ p
Key distinctions:
  • Descendant vs Child: descendant goes any depth; child is strictly one level down. Child is more restrictive.
  • Adjacent vs General sibling: adjacent matches only the next element (exactly one); general matches all that follow. Both require the two elements to share the same parent — unlike descendant/child, siblings don't look at nesting.
🔁 Follow-up: Why does .first + p match only one element? Because + is the adjacent combinator — it matches the very next sibling of the specified type. If .first is a <p> and the next element is a <span>, then .first + p matches nothing, because the next sibling isn't a p. Swap the selector to .first + * or use ~ if you want more flexibility.
🔁 Follow-up: Does ~ also match elements inside a descendant? No. Both + and ~ only look at siblings within the same parent. In the demo below, .first ~ p matches the direct sibling paragraphs but not the p nested inside .nested — that one is a child of a different parent, so it isn't a sibling of .first.
🔁 Follow-up: When would you choose each one in real code?
  • Descendant (space): most forgiving — safe default when you don't know how deep the target sits. Common in scoped component styles like .card h2.
  • Child (>): when you want tight scoping — prevents styles from leaking into nested components. Very common in component CSS.
  • Adjacent (+): "style the element that follows this one" — perfect for spacing between specific pairs, or form labels followed by their inputs.
  • General sibling (~): "style everything after this marker" — great for state-based rules like .toggle:checked ~ .panel (the classic CSS-only tab/dropdown pattern).

Q117 — What is the difference between :first-child, :first-of-type, and :nth-child()? Medium

✅ Ideal answer
  • :first-child selects an element if it is the first child of its parent — regardless of what type it is.
  • :first-of-type selects the first sibling of that particular element type — even if other elements come before it.
  • :nth-child(n) selects an element based on its position among its parent's children — it checks the position first, then the type.
🔁 Follow-up: Given a div with an h2 followed by two p tags, will p:first-child select the first paragraph? No — because the first child of the div is the <h2>, not a <p>. But p:first-of-type would select the first <p>.
🔁 Follow-up: Does :nth-child(2) mean "the second p"? No — it means "the element at position 2, if it matches the type." If position 2 is a <span>, then p:nth-child(2) matches nothing. To mean "the second p", use p:nth-of-type(2).

Q118 — Why does line-height: 1.5 behave differently from line-height: 150% and line-height: 1.5em when inherited? Medium

✅ Ideal answer All three declare the same line-height on the element that writes them — but they inherit differently:
  • line-height: 1.5 (unitless) — inherits as the number 1.5. Each descendant recomputes 1.5 × its own font-size. Result: larger text = proportionally taller lines, and vice versa.
  • line-height: 150% — inherits as a computed pixel value (parent's font-size × 1.5). Every descendant inherits that fixed px value — even if its own font-size is much larger.
  • line-height: 1.5em — behaves like the percentage. em on line-height resolves to pixels at the declaring element, and that px value is what inherits.
Rule of thumb: always use unitless line-height on parents — especially on body. It's the only form where each element scales its line-height to its own text.
🔁 Follow-up: Why does this only happen with line-height and not font-size? Because font-size's percentage is resolved immediately against the parent, producing a fixed pixel value that children inherit as that fixed value. There's no "re-compute later" behavior. line-height is special because the CSS spec allows the unitless form to inherit as a number, which defers the multiplication to each element.
🔁 Follow-up: What about line-height: 1.5rem or 24px? Both behave like the percentage — they inherit the fixed pixel value. 1.5rem computes to 1.5 × root font-size (e.g. 24px) at the declaring element, and every descendant inherits 24px regardless of its own text. Only the unitless number recomputes per element.

💻 Code

style.css — Visual Studio Code
style.css
/* ✅ Unitless — each element recomputes */
.wrapper-ok {
  font-size: 14px;
  line-height: 1.5;    /* inherits as the NUMBER 1.5 */
}
.wrapper-ok .small { font-size: 14px; }  /* 14 × 1.5 = 21px */
.wrapper-ok .large { font-size: 32px; }  /* 32 × 1.5 = 48px */

/* ❌ Percentage — inherits a frozen pixel value */
.wrapper-bad {
  font-size: 14px;
  line-height: 150%;   /* computes to 21px, then inherits as 21px */
}
.wrapper-bad .small { font-size: 14px; }  /* 21px */
.wrapper-bad .large { font-size: 32px; }  /* 21px — cramped! */

Q119 — What is the difference between inherit, initial, unset, and revert? Hard

✅ Ideal answer
  • inherit: Forces the property to take the computed value from the parent.
  • initial: Resets the property to its CSS-defined initial value.
  • unset: Acts as inherit for inherited properties and initial for non-inherited properties.
  • revert: Rolls the property's value back to a previous level of the cascade.
🔁 Follow-up: What is the difference between initial and inherit? initial uses the property's defined initial value, while inherit explicitly takes the value from the parent.

Q120 — What is the difference between width: min-content, max-content, and fit-content? Medium

✅ Ideal answer All three keywords tell the browser to compute the width from the element's content — but each uses a different "intrinsic" size:
  • min-content: The width of the widest unbreakable unit (usually the longest word). Text wraps as tightly as possible.
  • max-content: The width the content would need if it were laid out on a single line. No wrapping at all. Can overflow the parent.
  • fit-content: A hybrid — shrinks to fit the parent if it's too narrow, but never grows beyond max-content if the parent is wide.
In one sentence: min-content = tightest, max-content = widest, fit-content = just right.
🔁 Follow-up: Is width: fit-content the same as width: auto? Not for block-level elements. width: auto on a block makes it fill the parent's full width (default behavior). fit-content makes the element shrink to its content — perfect for inline-block-like behavior without changing display mode. However, for flex items and inline-block elements, auto already sizes to content — so fit-content is only interesting for regular blocks.
🔁 Follow-up: When would I actually use these?
  • min-content: Table cells, tight columns, "no narrower than this" constraints.
  • max-content: Buttons that should never wrap, single-line tags, tooltips — everything keeps its natural width.
  • fit-content: Card titles, tags, centered content that shouldn't span the full row. Equivalent to inline-block but for blocks.
Bonus: fit-content also accepts an argument: width: fit-content(300px) — shrink to content but cap at 300px.

💻 Code

style.css — Visual Studio Code
style.css
.min  { width: min-content; }   /* tightest — text wraps word-by-word */
.max  { width: max-content; }   /* widest — one long line, may overflow */
.fit  { width: fit-content; }   /* just right — as wide as content, but ≤ parent */
