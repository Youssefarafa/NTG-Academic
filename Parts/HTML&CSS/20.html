Q191 — What is the difference between reflow (layout) and repaint? Hard

✅ Ideal answer Reflow/Layout happens when the browser needs to recalculate the geometry or position of elements (e.g., changing width, margin).

Repaint happens when the browser needs to redraw pixels without necessarily recalculating layout (e.g., changing background-color).

Changing transform or opacity can often skip layout and paint, going straight to compositing.
🔁 Follow-up: Which is generally cheaper: changing transform or changing width during an animation? transform is often more animation-friendly because it can avoid layout recalculation, whereas changing width generally affects layout.

💻 Code

style.css — Visual Studio Code
style.css
/* Triggers Repaint + Composite */
.transform-box:hover { transform: translateX(100px); }

/* Triggers Layout/Reflow + Paint + Composite */
.width-box:hover { width: 200px; }

Q192 — What is compositing in browser rendering? Hard

✅ Ideal answer After layout and paint, the browser may divide content into layers and composite those layers together to produce the final image.

Properties such as transform and opacity can often be handled efficiently during compositing without requiring layout recalculation.
🔁 Follow-up: Why can transform and opacity be good choices for animations? They can often be updated during the compositing stage without requiring layout recalculation, which can make animations smoother.

💻 Code

style.css — Visual Studio Code
style.css
.layer-box {
  will-change: opacity; /* Hint to browser to composite this layer */
  transition: opacity 0.5s;
}
.layer-box:hover { opacity: 0.5; }

Q193 — What are CSS logical properties, and why are they useful? Medium → Hard

✅ Ideal answer Logical properties describe dimensions and spacing based on the writing direction, rather than physical left/right/top/bottom directions.

Instead of margin-left: 20px;, we use margin-inline-start: 20px;. This makes layouts adapt naturally to LTR (English) and RTL (Arabic) without rewriting CSS.
🔁 Follow-up: Why is this particularly useful for Arabic applications? Arabic uses RTL text direction. Logical properties allow the layout to adapt more naturally without manually replacing every left with right.

💻 Code

style.css — Visual Studio Code
style.css
.box {
  margin-inline-start: 20px; /* Left in LTR, Right in RTL */
  padding-block-start: 10px; /* Top in horizontal writing modes */
}

Q194 — What is the difference between direction: ltr/rtl and dir="ltr/rtl"? Medium

✅ Ideal answer dir is an HTML attribute that defines the text direction and is generally preferred when the direction is semantic/document-level information.

direction: rtl; is a CSS property that controls the direction visually. In a web application, I'd generally use the HTML dir attribute for document direction and use CSS logical properties for styling.
🔁 Follow-up: How would you support an application that can switch between Arabic and English? I can switch the document direction using <html dir="rtl"> dynamically, while using logical CSS properties (e.g., margin-inline-start) instead of hardcoded left/right styles.
🔁 Follow-up: What is the purpose of the dir attribute? dir specifies the directionality of text.

Common values:
ltr → left-to-right
rtl → right-to-left
auto → browser determines direction based on content

For example:
<html lang="ar" dir="rtl">
For English:
<html lang="en" dir="ltr">
🔁 Follow-up: Is dir the same as CSS direction? They're related but not identical.

dir is an HTML semantic attribute describing text directionality and can affect bidi behavior. CSS direction is a CSS property controlling direction in presentation/layout contexts.

For document text direction, using the semantic HTML dir attribute is often preferable.

💻 Code

index.html — Visual Studio Code
index.html
<html dir="rtl"> <!-- Semantic HTML direction -->
  <body>
    <div style="direction: ltr;">CSS direction override</div>
  </body>
</html>

Q195 — How do you make a CSS form accessible? Hard

✅ Ideal answer I'd combine semantic HTML with appropriate CSS. I would ensure:
  • Every input has an associated <label>.
  • Focus states are clearly visible (e.g., using :focus-visible).
  • Error states aren't communicated only through color (add icons/text).
  • Sufficient color contrast is maintained.
🔁 Follow-up: Is color alone enough to communicate an error? No. For example, I shouldn't rely only on a red border. I should also provide text or another accessible indication.

💻 Code

style.css — Visual Studio Code
style.css
input:focus-visible {
  outline: 3px solid #4f46e5;
  outline-offset: 2px;
}

.error-msg {
  color: #ef4444;
  /* Include an icon or text to avoid relying on color alone */
}

Q196 — What is accent-color in CSS? Medium

✅ Ideal answer accent-color allows us to customize the accent color used by certain native form controls (like checkboxes and radio buttons). This provides visual customization while keeping the browser's native control behavior.
🔁 Follow-up: Does accent-color completely redesign the checkbox? No. It primarily changes the accent color. If I need complete visual control, I may need custom styling, but then I have to be careful not to break accessibility.

💻 Code

style.css — Visual Studio Code
style.css
input[type="checkbox"],
input[type="radio"] {
  accent-color: #4f46e5;
}

Q197 — What are responsive images, and why are srcset and sizes useful? Hard

✅ Ideal answer Responsive images allow the browser to choose an appropriate image resource based on factors such as viewport size and display density.

srcset provides multiple image candidates. sizes tells the browser approximately how much viewport width the image will occupy under different conditions. This can prevent downloading unnecessarily large images.
🔁 Follow-up: Why not always send the largest image? Because it wastes bandwidth and can increase loading time, especially on mobile or slower connections.

💻 Code

index.html — Visual Studio Code
index.html
<img
  src="small.jpg"
  srcset="
    small.jpg 480w,
    medium.jpg 800w,
    large.jpg 1200w
  "
  sizes="(max-width: 768px) 100vw, 50vw"
  alt="Plant"
>

🔴 Live demo (Resize window slowly)

The browser chooses the best image size based on your screen width.

Q198 — What is object-position? Medium

✅ Ideal answer object-position controls the position of replaced content such as an image within its content box, especially when using object-fit: cover. If the image gets cropped, object-position determines which part remains visible.
🔁 Follow-up: What happens with `object-position: center;`? The image is positioned around its center, so cropping is generally distributed around the center rather than favoring one edge.

💻 Code

style.css — Visual Studio Code
style.css
img {
  object-fit: cover;
  object-position: center top;
}

Q199 — What is CSS nesting? Medium

✅ Ideal answer CSS nesting allows selectors to be nested inside another CSS rule.

It provides some of the nesting convenience historically associated with preprocessors like Sass, while being supported natively by modern browsers.
🔁 Follow-up: Is CSS nesting the same as Sass nesting? They solve a similar problem but aren't identical technologies. Native CSS nesting is implemented by the browser, while Sass nesting is processed during compilation.

💻 Code

style.css — Visual Studio Code
style.css
.card {
  padding: 20px;

  & .title {
    font-size: 20px;
  }

  &:hover {
    transform: translateY(-2px);
  }
}

Q200 — How would you organize CSS in a large Angular application? Hard

✅ Ideal answer I would avoid putting everything into one huge global stylesheet. I'd separate styles based on responsibility:
  • Global: variables/tokens, typography, reset/base, utilities.
  • Components: buttons, forms, cards, tables.
  • Pages/Layouts: dashboard, authentication, application shell.
In Angular, I'd primarily keep component-specific styles close to their components and reserve global styles for things that genuinely need to be global. I'd also minimize !important and reuse design tokens.
🔁 Follow-up: Suppose your Angular application uses PrimeNG + Tailwind. How would you prevent style conflicts? Establish clear responsibilities: PrimeNG for component behavior, Tailwind for utility/layout, component styles for local customization, and a global theme for design tokens. Avoid randomly mixing competing approaches on the same property.
