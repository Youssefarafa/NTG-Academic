Q91 — What is the difference between block, inline, and inline-block elements? Easy → Medium

✅ Ideal answer The difference is mainly how the element participates in the layout.
  • block elements normally start on a new line and can take the available width.
  • inline elements flow within the surrounding text and generally don't accept width and height in the same way block-level elements do.
  • inline-block flows inline but still allows width and height to be applied.
🔁 Follow-up: Is <div> always block and <span> always inline? By default, yes in normal HTML user-agent styling, but CSS can change their display behavior.

💻 Code

style.css — Visual Studio Code
style.css
.block { display: block; }
.inline { display: inline; }
.inline-block { 
  display: inline-block;
  width: 200px;
  height: 100px;
}

Q92 — What is the difference between width: 100% and width: 100vw? Medium

✅ Ideal answer width: 100% means the element tries to occupy 100% of the width of its containing block.

100vw means 100% of the viewport width.

They can produce different results when the containing block doesn't have the same width as the viewport.
🔁 Follow-up: Why can 100vw sometimes cause horizontal scrolling? Because vw is based on the viewport width, and depending on the browser and scrollbar behavior, 100vw can include the scrollbar area. This can make the element slightly wider than the available layout area.

💻 Code

style.css — Visual Studio Code
style.css
.container {
  width: 100%;
}

.full-screen {
  width: 100vw;
}

Q93 — What is the difference between em, rem, %, vh, and vw? Medium

✅ Ideal answer
  • % is generally relative to a relevant containing/reference dimension.
  • em is relative to the computed font size of the element (or parent).
  • rem is relative to the root element's font size.
  • vh is relative to the viewport height.
  • vw is relative to the viewport width.
🔁 Follow-up: Why is rem often preferred over em for consistent sizing systems? Because rem is based on the root font size, which makes sizing more predictable and avoids some of the compounding behavior that can happen with nested em values.

💻 Code

style.css — Visual Studio Code
style.css
html { font-size: 16px; }

.title {
  font-size: 2rem; /* Equals 32px */
}

Q94 — What is the CSS box model? Easy → Medium

✅ Ideal answer The CSS box model describes how an element's dimensions are composed of:
Content → Padding → Border → Margin.

The actual space occupied depends on the box-sizing model.
🔁 Follow-up: What is the difference between content-box and border-box? With content-box, the specified width and height apply to the content area. With border-box, the specified dimensions include the content, padding, and border.

💻 Code

style.css — Visual Studio Code
style.css
.content-box {
  box-sizing: content-box;
  width: 200px;
  padding: 20px;
  border: 5px solid;
}

.border-box {
  box-sizing: border-box;
  width: 200px;
  padding: 20px;
  border: 5px solid;
}

Q95 — What is the difference between margin collapsing and padding? Medium → Hard

✅ Ideal answer Padding is space inside the element, between its content and border.
Margin is space outside the element.

Vertical margins between certain block-level elements can collapse, meaning they don't necessarily add together; the resulting margin can be the larger of the adjoining margins under the applicable rules.
🔁 Follow-up: Does padding collapse? No. Padding doesn't participate in margin collapsing.

💻 Code

style.css — Visual Studio Code
style.css
.first {
  margin-bottom: 30px;
}

.second {
  margin-top: 20px;
}
/* The gap between them will be 30px, not 50px! */

Q96 — What is CSS specificity? Medium

✅ Ideal answer Specificity is the algorithm browsers use to determine which competing CSS selector has higher priority.

Simplified hierarchy:
Inline styles → IDs → Classes/Attributes/Pseudo-classes → Elements.
🔁 Follow-up: What is !important? !important changes the priority of a declaration within the cascade, but it should be used sparingly because excessive use makes CSS harder to maintain.

💻 Code

style.css — Visual Studio Code
style.css
div { color: blue; }        /* Element  (0,0,1) */
.my-class { color: green; } /* Class    (0,1,0) */
#my-id { color: red; }      /* ID       (1,0,0) */

Q97 — What is the difference between pseudo-class and pseudo-element? Medium

✅ Ideal answer A pseudo-class represents a state or condition of an element (e.g., :hover, :focus).

A pseudo-element represents a particular part of an element or generated content (e.g., ::before, ::first-letter).
🔁 Follow-up: What's the difference between :hover and ::before? :hover targets an element when it is in a particular state, while ::before represents a pseudo-element generated before the element's content.

💻 Code

style.css — Visual Studio Code
style.css
/* Pseudo-class */
button:hover { background: red; }

/* Pseudo-element */
p::before { content: "👉 "; }

Q98 — What is a stacking context, and how is it related to z-index? Hard

✅ Ideal answer A stacking context is a conceptual group of elements that the browser paints together according to stacking rules.

z-index controls stacking order within the relevant stacking context, but a child cannot simply use a huge z-index to escape its parent's stacking context and appear above everything else.

Certain properties and conditions can create stacking contexts, such as positioned elements with a non-auto z-index, opacity less than 1, and transforms.
🔁 Follow-up: Why doesn't a child with z-index: 999999 always appear on top? Because the child is still constrained by the stacking context created by its ancestors. Its z-index is compared within its stacking context rather than globally against every element on the page.

💻 Code

style.css — Visual Studio Code
style.css
.parent {
  position: relative;
  z-index: 1; /* Creates a stacking context */
}

.child {
  z-index: 999999; /* Trapped inside parent! */
}

.sibling {
  position: relative;
  z-index: 2; /* Will appear ABOVE the child */
}

Q99 — What is the difference between reflow and repaint? Hard

✅ Ideal answer Reflow (or layout) happens when the browser needs to recalculate the geometry or layout of elements.

Repaint happens when the browser needs to redraw pixels without necessarily recalculating the layout.

Changing width, height, or margin can trigger layout work. Changing a visual property like background-color can require repaint without layout.
🔁 Follow-up: Why are transform and opacity commonly preferred for animations? They can often be handled more efficiently by the rendering pipeline and can avoid repeated layout calculations, making them good candidates for smooth animations.

💻 Code

style.css — Visual Studio Code
style.css
/* Triggers Reflow (Layout) */
.janky { transition: width 0.3s; }
.janky:hover { width: 200px; }

/* Triggers only Compositing (Smooth) */
.smooth { transition: transform 0.3s; }
.smooth:hover { transform: translateX(100px); }

Q100 — What is the Critical Rendering Path? Hard

✅ Ideal answer The Critical Rendering Path is the sequence of steps the browser goes through to turn HTML, CSS, and JavaScript into rendered pixels.

HTML → DOM
CSS → CSSOM
DOM + CSSOM → Render Tree
Render Tree → Layout → Paint → Compositing
🔁 Follow-up: Why can CSS block rendering? Because the browser needs the relevant CSS information to determine how elements should be rendered. Stylesheets can therefore affect the rendering process, especially for content that depends on them.
🔁 Follow-up 2: How can JavaScript negatively affect initial page load? A synchronous script can block HTML parsing while it is fetched and executed. Large JavaScript bundles can also increase parsing, compilation, execution, and memory costs.
